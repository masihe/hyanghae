# 자연어 추천 — 측정 기록과 트러블슈팅

자연어 추천 시스템을 설계하면서 실제로 발견하고 측정한 것들. 설계 결정의 근거이면서, 프로젝트 회고와 포트폴리오의 소재.

기록 형식: **문제 → 어떻게 발견했나 → 측정 → 판단 → trade-off**

| # | 제목 | 한 줄 |
|---|---|---|
| 1 | 의미는 맞는데 검색이 안 되는 매핑 | LLM이 제안한 accord의 코퍼스 지지도가 1개 |
| 2 | 한국어 "머스크"는 영어 musk가 아니다 | 매핑은 맞지만 의도한 향은 결과의 1% |
| 3 | avoid F1 0.000의 실체는 채점기였다 | 모델은 맞혔는데 표기가 달라서 0점 |
| 4 | 잘 만든 향 어휘 사전이 실사용의 12%만 덮는다 | 와인 도메인의 독립 측정치와 일치 |
| 5 | Fragrantica의 향 계열 라벨이 description 안에 있었다 | 컬럼에 없는 필드를 문장에서 복원 |

| 7 | 평가셋이 팀원 작성이라 실사용보다 쉽다 | 실사용은 2.4배 길고 조건이 2배 많다 |

## 1. 의미는 맞는데 검색이 안 되는 매핑

### 문제

자연어 표현을 Fragrantica accord로 바꾸는 실험(노트북 23)에서, LLM이 "비 온 뒤의 숲의 냄새"를 `foresty` + `earthy`로 변환했다. 사람이 봐도 타당한 매핑이었다.

### 어떻게 발견했나

변환 결과를 그대로 승인하지 않고, **각 후보 accord를 실제로 검색했을 때 향수가 몇 개 나오는지** 계산했다.

```python
S = df.accords.fillna('').map(lambda s: set(p.split(':')[0] for p in s.split('|') if p))
def and_count(targets): return sum(1 for x in S if set(targets) <= x)
```

### 측정

전체 131,930개 기준.

| accord | 보유 향수 |
|---|---:|
| `foresty` | **1** |
| `wet plaster` | 2 |
| `soapy` | 1,720 |
| `musky` | 41,154 |

파일럿 12건 전체를 검색 결과 크기로 분류한 결과:

| 판정 | 건수 |
|---|---:|
| 쓸만함 | 6 |
| 검색 결과 0~1개 | **3** (전부 `foresty` 때문) |
| 너무 넓음 (33,478개) | 1 |
| LLM이 포기 | 2 |

accord 92개 중 보유 향수가 1,000개 미만인 것이 **36개**, 10개 미만인 것이 **11개**였다.

### 판단

**"의미가 맞는가"만으로 매핑 품질을 판정하면 이 실패를 놓친다.** Domain Lexicon 항목마다 `corpus_support`(해당 accord를 가진 향수 수)를 필수 컬럼으로 두기로 했다.

이 정보는 **LLM이 구조적으로 알 수 없다.** `foresty`가 우리 데이터에 몇 개인지는 세상 지식이 아니라 우리 데이터 안에만 있는 사실이라, 모델을 키우거나 프롬프트를 고쳐서 해결되지 않는다. 렉시콘이 LLM보다 확실히 나은 지점이 바로 여기다.

### Trade-off

- 렉시콘 항목을 추가할 때마다 코퍼스 집계를 다시 돌려야 한다 → 스크립트로 자동화
- 지지도가 낮다고 항목을 지우면 의미적으로 정확한 표현을 잃는다 → 지우지 않고 값만 기록하고, 검색 단계에서 판단

## 2. 한국어 "머스크"는 영어 musk가 아니다

### 문제

`머스크향` → `musky`는 외래어 그대로라 안전해 보이는 매핑이다. 실제로 LLM도 이렇게 변환한다.

### 어떻게 발견했나

한국어 향수 커뮤니티·커머스 문서를 조사하다가, 한국에서 "머스크"가 사실상 **화이트머스크**(세탁·비누 느낌)를 가리킨다는 지적을 발견했다. Fragrantica의 `musky`는 애니멀릭까지 포괄한다.

주장으로 끝내지 않고 코퍼스에서 검증했다.

### 측정

```
musky 보유              41,154  (전체의 31.19%)
  ├ soapy 동반             400  (musky의 1.0%)     ← 한국어 화자가 뜻하는 쪽
  ├ powdery 동반         70.9%
  ├ woody 동반           59.3%
  └ animalic 동반        18.9%                     ← 반대쪽
```

역방향도 확인했다. `soapy` 보유 1,720개 중 `musky`를 같이 가진 것은 400개(23.3%)다.

### 판단

`머스크향 → musky`는 **틀린 매핑이 아니라 무효한 매핑**이다. 코퍼스의 31%를 반환하면서 의도한 의미는 그중 1%다. 변별력이 거의 없다.

렉시콘에 `caution` 컬럼을 두고 이런 내용을 명시적으로 적기로 했다.

```
머스크 → musky   caution: "단독 사용 금지. 코퍼스 31%, 의도한 화이트머스크는 그중 1.0%"
                 대안: soapy + musky + fresh 조합
```

부수적으로, "외래어는 1:1이라 쉽다"는 가정이 틀렸다는 것도 확인했다. **외래어 층도 항목마다 감사가 필요하다.**

### Trade-off

- `soapy`(1,720개)를 필수 조건으로 걸면 결과가 매우 좁아진다 → 필수/보조를 구분하고 좁으면 완화
- 한국어 사용자의 의도를 우선하면 애니멀릭 머스크를 원한 소수 사용자를 놓친다 → 문맥 조건으로 분기

## 3. avoid F1 0.000의 실체는 채점기였다

### 문제

Stage 1 평가에서 `avoid`(회피 조건) 항목의 F1이 **정확히 0.000**이었다. 36건 전부 틀렸다는 뜻이다.

처음에는 "LLM이 부정 표현의 범위를 이해하지 못한다"고 해석했고, 모델이나 프롬프트를 개선하는 방향을 검토했다.

### 어떻게 발견했나

**정확히 0.000이라는 게 이상했다.** 부분 점수가 조금이라도 나와야 자연스러운데 완전한 0이었다. 36건 전부를 눈으로 열어봤다.

### 측정

| 정답(gold) | 모델 출력(pred) | 채점 |
|---|---|---|
| 머스크 | musk | 0점 |
| 우디 | woody | 0점 |
| 파우더리 | powdery | 0점 |
| 시트러스 | citrus | 0점 |
| 바닐라 | Vanilla | 0점 |
| 복숭아, 체리 | Peach, Cherry | 0점 |
| 인위적인 | 인위적인 향 | 0점 |

**모델은 맞혔다.** "머스크는 빼줘"를 읽고 `musk`를 정확히 뽑았다. 정답이 한국어 원문 조각이고 채점이 문자열 완전 일치라서 0점이었다.

36건 중 **진짜로 못 뽑은 건 11건**, 나머지 **25건은 맞혔는데 표기가 달라서 0점**이었다.

`additional_requirements`도 같은 문제였다. 정답이 원문에서 글자 그대로 잘라낸 조각이어야 하는데 모델은 조금 길게 자르거나 다듬어 쓴다.

| 질문 | 정답 | 모델 출력 |
|---|---|---|
| 시트러스 계열의 깔끔한 향의 향수가 있어? | `깔끔한` | `깔끔한 향` |
| 비가 온 뒤의 숲같은 향을 찾고 있어 | `비가 온 뒤`, `숲` | `비가 온 뒤의 숲같은 향` |

모델 출력을 하나도 바꾸지 않고(API 재호출 0회) 채점기만 고쳐서 다시 계산했다.

처음에는 즉석 정규화로 avoid 0.507 / additional 0.569를 얻었다. 그 뒤 노트북 25에서
규칙을 층으로 나눠 사전 등록하고 정식으로 재채점했고, QA 60건으로 gold 오류까지 분리했다.
**아래가 확정 수치다.**

| 단계 | avoid | additional | 대상 |
|---|---:|---:|---:|
| ① 원래 채점 | **0.000** | 0.124 | 36 / 170 |
| ② 채점 규칙 수정 (노트북 25) | **0.493** | **0.337** | 36 / 170 |
| ③ ② + gold 오류 13건 보정 가정 | **0.653** | — | 23 |

③은 진단용 가정 계산이고 평가 데이터는 수정하지 않았다.

층별 기여 (avoid, LLM) — `L0 0.000 → L2 별칭 0.319 → L3 접미사 0.435 → L4 포함 0.493`.
`L1 구두점`은 이 데이터에서 기여가 정확히 0이었고 그대로 보고했다.

그리고 ③ 이후 남은 FN 9건 중 **8건이 번역·의역**이고 예측이 빈 것은 1건뿐이다.

```
36건 중
  13건  정답 라벨이 잘못됨        ← QA로 발견
  22건  맞혔는데 표기가 달라 0점   ← 채점기 문제
   1건  진짜로 못함
```

### 판단

**자가 틀어져 있었다.** 이 상태에서 모델을 개선하면 "정답의 자르기 습관을 흉내내도록" 튜닝하게 되고, 그건 추천 품질과 무관하다.

작업 순서를 바꿨다.

1. 채점 기준을 팀이 정한다 (한국어↔영어를 같다고 볼 것인가, 부분 일치를 어디까지 인정할 것인가)
2. 이미 준비돼 있던 Golden Set QA 60건을 판정한다 (`16_golden_set_quality_audit_candidates.csv`, 당시 0/60)
3. 저장된 LLM 응답(`15_llm_stage1_checkpoint.csv`)으로 재채점 → 진짜 baseline 확보
4. 그 다음에 개선 방향을 정한다

그리고 채점기를 고치는 데 필요한 것이 `머스크=musk`, `우디=woody` 같은 20~30줄짜리 표라는 점을 확인했다. **이건 Domain Lexicon의 가장 싼 조각이다.** 렉시콘 작업과 평가 정상화가 경쟁 관계가 아니라 같은 부품을 공유한다.

### Trade-off

- 부분 일치를 관대하게 허용하면 실제보다 좋게 나온다 → `MAX_EXCESS_TOKENS = 1`을 사전 등록하고 고정했다.
  0/1/2/3/무제한을 전부 계산했는데 무제한은 Extended Rule의 과포획 span까지 득점시켜 채택하지 않았다
- 규칙 오지정은 0건이다. QA에서 "예측이 실제로 틀렸다"고 판정한 건에 규칙이 점수를 준 사례가 없다
- 평가 데이터 자체는 수정하지 않았다 (메모리에서만 재계산)
- 남은 8건의 번역·의역을 잡으려면 별칭표를 키워야 하는데, 그건 **내가 내린 판정에 맞춰 내가 만든
  규칙을 조정하는 것**이 된다. 파라미터를 판정 전에 사전 등록한 이유가 이것이라 고치지 않았다

## 4. 잘 만든 향 어휘 사전이 실사용의 12%만 덮는다

### 문제

팀이 Michael Edwards의 14개 향 계열 기준으로 한국어 묘사 어휘 문서(2,813줄)를 만들었다. 이걸 Domain Lexicon의 기반으로 쓸 계획이었다.

### 어떻게 발견했나

문서를 그대로 신뢰하지 않고, **실제 사용자 쿼리 200개에서 뽑은 표현 346개와 대조**했다(노트북 24). 그리고 다른 도메인에 같은 측정이 있는지 찾아봤다.

### 측정

**우리 데이터:**

```
MATCHED     43  (12.4%)   문서에 명시된 표현과 일치
RELATED    105  (30.3%)   부분 문자열 또는 활용형
NOT_FOUND  198  (57.2%)   근거 없음
```

역할별로 나누면 어디가 비었는지 보인다.

| 표현 종류 | 커버리지 |
|---|---:|
| SENSORY (형용사) | 91.4% |
| DIRECT_SCENT | 77.3% |
| SOURCE (물건 이름) | 58.6% |
| IMAGE | 48.3% |
| **SCENE (장면 비유)** | **36.0%** — 정확 일치 0건 |

**외부 비교:**

Croijmans et al. (2020), *Natural Language Engineering* 26(5). 와인 전문가 리뷰 73,329건에서 실사용 용어 146개를 추출하고 고전 와인 향 사전 3종(244개 용어)과 대조 → **겹치는 것 34개, 13.9%.** 반대로 13명 전원이 쓰는데 어느 사전에도 없는 용어가 89개.

우리 12.4%와 독립적으로 관측된 13.9%가 거의 같다.

### 판단

**12%는 문서의 결함이 아니라 이런 종류 자산의 일반적 성질이다.** 그러므로 "어휘를 더 모으자"는 방향은 효과가 없다.

방향을 바꿨다.

- 문서를 키우는 대신, **실제 사용자 표현에서 출발해 역으로 채운다**
- 초기 목표를 30~50개 항목으로 잡는다 (발표된 감각 사전 대부분이 14~40개)
- 문서가 이미 잘하는 형용사(91.4%)가 아니라, **비어 있는 장면 비유(36.0%)에 집중한다**

### Trade-off

- 항목 수가 적으면 미등록 표현이 늘어난다 → 매칭 실패를 로그로 남기고 주기적으로 후보 검토
- 실제 쿼리에서 항목을 뽑으면 그 쿼리로 평가할 때 leakage가 생긴다 → `source_query_ids`를 기록해 seen/unseen 분리

## 5. Fragrantica의 향 계열 라벨이 description 안에 있었다

### 문제

한국어 묘사 문서는 **Michael Edwards의 14개 향 계열** 기준이고, 검색 데이터는 **Fragrantica accord 92개** 기준이다. 두 축을 잇는 연결이 없었다. `perfumes.csv` 59개 컬럼에 향 계열 필드는 없다.

### 어떻게 발견했나

`description` 컬럼의 실제 값을 눈으로 확인하다가 첫 문장의 패턴을 발견했다.

> "Orange Tonic by Azzaro is a **Floral Green** fragrance for women."

컬럼에는 없지만 문장에는 들어 있었다.

### 측정

대문자로 시작하는 1~4개 토큰만 받는 보수적 정규식으로 추출했다.

```python
pat = re.compile(r'\bis an? ((?:[A-Z][a-z]+ ){0,3}[A-Z][a-z]+) fragrance for (?:women|men)')
```

```
추출 성공     110,163건 = 전체의 83.50%
서로 다른 라벨      35개
기본 용어           16개

Floral 52,306 · Oriental 32,117 · Woody 29,216 · Aromatic 21,324
Fruity 18,965 · Spicy 8,846 · Musk 8,081 · Citrus 6,140 · Vanilla 5,592
Gourmand 5,112 · Chypre 4,571 · Green 3,458 · Aquatic 3,425
Fougere 3,255 · Leather 2,367 · Aldehyde 790
```

미매칭 16.5%는 파싱 실패가 아니라 group 자체가 없는 레코드였다("is a fragrance for women").

### 판단

기본 용어 16개는 Edwards의 14개 계열과 상당히 가깝다 (Chypre↔Mossy Woods, Fougere↔Aromatic Fougère, Oriental↔Amber 계열). **한국어 문서와 Fragrantica 사이의 끊긴 연결을 이을 후보 축**이 될 수 있다.

accord의 심한 편중 문제도 완화한다. 최소 라벨인 Aldehyde도 790건이라, `foresty`의 1건 같은 붕괴가 없다.

### Trade-off와 미확인 사항

- **이것이 Fragrantica의 공식 group 필드인지 문서로 확인하지 못했다.** 추정이다
- 라벨이 없는 16.5%를 어떻게 다룰지 정해야 한다
- 정규식 추출이므로 원본 데이터가 바뀌면 깨질 수 있다
- 채택하려면 위 세 가지를 먼저 정리해야 한다

## 6. 같은 뜻을 다르게 쓰면 다른 향수가 나온다

### 문제

사용자 A는 `달콤한`, 사용자 B는 `달큰한`이라고 쓴다. 같은 말이다.
둘이 다른 accord로 가면 같은 취향에 다른 향수가 추천된다.

이 질문의 답이 사전 규모를 정한다. LLM이 알아서 처리하면 사전은 작아도 되고,
못 하면 변형어 층을 사전이 담아야 한다.

### 어떻게 발견했나

사전 커버리지를 재보니 새 쿼리의 **8.2%**밖에 못 덮었다(표현 346개 중 93%가 1회만 등장).
어간으로 묶어도 15.8%였고, 묶인 12건이 전부 `깨끗하고/깨끗한/깨끗함` 같은 활용형이었다.
`달콤한/달큰한`처럼 **다른 단어**는 하나도 안 묶였다.

그래서 "표현을 나열하는 건 불가능하니 LLM에 맡기고 사전은 교정만 하자"는 가설을 세웠고,
**그 가설을 측정했다.**

### 측정 (노트북 26)

팀 문서 `perfume_14families_korean_descriptors.md` 20-B/19장에서 변형어 21쌍을 가져왔다.

설계에서 중요한 것 두 가지.

- **표준형과 변형형을 서로 다른 요청으로 보냈다.** 같은 요청에 나란히 넣으면 모델이 둘을 보고
  억지로 일관되게 답할 수 있다
- **정답을 사람이 정하지 않았다.** 두 답이 서로 같은지만 봤다

```
accord 집합 완전 일치      2/21 (10%)
1순위 accord 일치          7/21 (33%)
AND 검색 Jaccard 중앙값     0.8%
점수 검색 TOP50 겹침 중앙값   0.0%   ← 21쌍 중 15쌍이 전혀 겹치지 않음
허용 목록 밖 accord 생성     3종 (sharp, dry, rain)
```

```
달콤한 → 138개      달큰한 → 3,745개      교집합 17개
```

### 판단

**LLM 단독으로는 안 된다.** 그런데 유형별로 갈렸고, 여기가 결론이다.

| 유형 | 쌍 | 1순위 일치 | TOP50 겹침 |
|---|---:|---:|---:|
| 외래어 파생 (우디한, 바닐라리한) | 4 | **100%** | 27.0% |
| 철자 변형 (달큰한, 보송한) | 4 | **75%** | 25.0% |
| 방언·의태어 (쓸쿰한, 폭신한) | 5 | 0% | 0.8% |
| 문화적 비유 (절간 냄새, 에프킬라) | 7 | 0% | 0.3% |
| 커뮤니티 은어 (화플) | 1 | 0% | 0.0% |

님이 예로 든 `달콤한/달큰한`은 **LLM이 처리하는 쪽**이었다. 못 하는 건 한국 향수 커뮤니티
고유 어휘였다.

그런데 그 세 유형의 **실사용 빈도를 재보니 결론이 또 뒤집혔다** (→ `DECISIONS.md` N1).
설문 155건에서 은어 0.6%, 비유 0.6%, 방언은 19건 중 18건이 `달달` 하나였다.
반면 사전이 다루지 않던 **향수 전문 용어가 18.1%** 였다.

### Trade-off

- 92개 목록을 프롬프트에 명시했는데도 목록 밖 이름을 만들었다 → JSON Schema enum 강제가 필요하다
- 21쌍은 목적 표집이며 무작위 표본이 아니다. 이 비율을 전체 성능으로 일반화하지 않는다
- 단일 실행이고 모델 하나만 측정했다
- "1순위만 쓰기"가 33%로 나아 보이지만 순서가 불안정하다. `상큼한/상콤한`은 집합이 같은데
  순서가 달라 1순위로는 불일치가 됐다

## 7. 평가셋이 팀원 작성이라 실사용보다 쉽다

### 문제

Stage 1의 모든 숫자(Overall EM 6.0%, avoid F1, scent F1)가 `13_stage1_golden_set_v1_200.xlsx`
200건에서 나왔다. **이게 실사용을 대표하는가?**

### 어떻게 발견했나

Golden Set의 `Audit` 시트를 열어보다 `source_author` 컬럼을 발견했다.

```
김재성 35 · 송가연 26 · 차서영 23 · 김경린 21 · 권영민 21 · 김용석 20 · (미기재) 54
→ 팀원 6명이 작성
```

즉 **golden set은 팀원이 "사용자가 이렇게 물어보겠지" 하고 상상해 쓴 합성 데이터**이고,
`data/survey/processed/survey_nlp_queries_candidates.csv` 155건이 진짜 일반인 응답이다.

### 측정

| | golden 200 (팀원) | survey 155 (실사용자) |
|---|---:|---:|
| 평균 길이 | 30자 | **71자** |
| p90 | 42자 | **145자** |
| 최대 | 58자 | **600자** |
| 한 쿼리의 조건 수 (평균) | 1.3개 | **2.7개** |
| 조건 수 (최대) | 3개 | **20개** |
| 향수 전문 용어 | 5.5% | **18.1%** |

실사용에만 있는 것들.

```
[277자] "너는 최고급 니치 향수 전문 컨설턴트야. ... 각 향수마다 왜 골랐는지 자세히 설명해 줬으면"
        → 역할 부여 + 출력 형식 지정. 악의적 공격이 아니라 평범한 입력이다
[600자] "이 편지는 영국에서 최초로 시작되어..."
        → 행운의 편지. 향과 무관한 입력 처리가 필요하다
```

### 판단

golden set이 잘못됐다는 게 아니다. 라벨이 2명 검수로 붙어 있고 재현 가능한 비교 기준이다.
다만 **"실사용 성능 추정치"로 읽으면 안 된다.**

역할을 나눴다.

```
golden 200 (팀원 작성)  →  개발용 회귀 테스트
                          코드를 고쳤을 때 깨지는지 보는 용도.
                          여기서 나온 숫자를 "실사용 성능"이라고 부르지 않는다

survey 155 (실사용자)    →  외부 holdout
                          아직 라벨링 안 됨. 노트북 22가 12건 사용.
                          남은 143건을 라벨링하면 처음으로 실사용 성능을 잴 수 있다
```

`spec.md` §7.2에 "새 쿼리 60~100개를 수집해 동결"이라고 써뒀는데 **수집할 필요가 없다. 이미 있다.**

### Trade-off

- 실사용 성능은 지금 숫자보다 낮을 가능성이 크다. 조건이 20개인 쿼리에서 5개 필드가 전부
  정확히 맞을 확률은 조건 1개짜리보다 훨씬 낮다
- 설문 155건을 라벨링하려면 비용이 든다. 그리고 라벨링 전에 `avoid` 기준을 확정해야 한다
  (→ errata의 가이드 개정안). 안 그러면 같은 오분류가 반복된다
- 설문에도 한계가 있다. 인구통계 문항이 없어 응답자 구성을 알 수 없다

## 8. 같은 accord인데 단독이면 안 되고 조합하면 된다

### 문제

사전을 쓰기 전에 확인할 것이 있었다. **accord 92개로 사용자 표현을 담을 수 있는가.**
담을 수 없다면 사전이 accord만 겨냥하는 설계를 재검토해야 한다(`spec.md` §4.3).

`spec.md` §8 남은 작업 1번이 이 질문이었고, 답을 노트북 22의 사람 평가 70건에서 얻을 계획이었다.

### 어떻게 발견했나

70건을 판정하기 전에 **그 표가 실제로 무엇을 담고 있는지** 열어봤다.

세 가지가 나왔다. 첫째, 표는 **v1 실행 결과에 고정돼 있고 v1은 12건 중 7건이 스키마 검증에
실패했다**(`23_..._v2_checkpoint.json`의 `source_v1`: `schema_valid_count 5,
validation_failure_count 7`). LLM이 `target_type`에 선택지 문자열 `ACCORD|CANONICAL_NOTE`를
그대로 써서 계획 §6.3의 *"검증 후 target이 0개면 ABSTAIN으로 처리한다"* 에 걸린 것이다.
그 7건이 ABSTAIN 원인 판정 9건 중 7건을 차지한다. 노트북 23이 같은 7건을 전부 유효한 accord로
매핑했으므로 판정 결과는 이미 정해져 있다.

둘째, `retrieval_key`를 대조하니 **RETRIEVAL 53건 중 30건이 baseline과 treatment의 향수 집합이
동일**했다. v1이 ABSTAIN해서 treatment에 더할 bridge accord가 없었기 때문이다.
Δ Pooled Human NDCG@5가 구조적으로 0이므로 채점해도 정보가 나오지 않는다.

셋째, 그래서 **사람 판정이 답할 수 없는 축이 따로 있다는 걸 알았다.**

`비 온 뒤의 숲 → foresty` 는 의미상 정확한 번역이다. 평가자가 채점하면 `2 = STRONG`을 준다.
그런데 `foresty` 보유 향수는 13만 개 중 **1개**다. **사람 점수가 만점인데 기능은 동작하지 않는다.**

사전등록된 ABSTAIN 원인 분류 셋(`APPROPRIATE_ABSTENTION` / `TARGET_SPACE_LIMITATION` /
`MAPPING_FAILURE`)은 모두 *"적절한 target이 있는가"* 를 묻고, *"그 target이 변별력이 있는가"* 를
묻는 칸이 없다. 그래서 그 축을 계산했다(노트북 27).

### 측정

v2가 제안한 accord로 실제 검색했다. 두 값을 함께 냈다 — 후보 수와, strength 합으로 정렬했을 때
**상위 5위에 들려면 몇 개와 동점 경쟁을 하는가**.

**단독으로 쓰면 순위가 안 나온다.**

| accord | 보유 향수 | 전체 대비 | 최대 강도 동점 | 단독 5위 동점 |
|---|---:|---:|---:|---:|
| `citrus` | 59,969 | 46.4% | 17,736 | **17,736** |
| `warm spicy` | 45,319 | 35.1% | 6,281 | **6,281** |
| `fresh` | 33,478 | 25.9% | 830 | **830** |
| `earthy` | 19,049 | 14.7% | 533 | **533** |
| `aquatic` | 8,872 | 6.9% | 609 | **609** |
| `soapy` | 1,720 | 1.3% | 18 | 18 |
| `foresty` | 1 | 0.0% | 1 | 1 |

7종 중 **5종이 단독으로는 상위 5개를 고르지 못한다.** `citrus`는 17,736개가 똑같이 강도 100이다.

**조합하면 뒤집힌다.**

| 조합 | 후보 | 5위 동점 |
|---|---:|---:|
| `soapy` + `warm spicy` | 114 | **5** |
| `fresh` + `soapy` | 1,049 | **6** |
| `aquatic` + `fresh` | 4,963 | **14** |
| `fresh` + `citrus` | 18,826 | **25** |
| `musky` + `powdery` + `vanilla` | 8,007 | **9** |

`fresh`(25.9%)와 `citrus`(46.4%)는 각각 너무 넓지만 둘을 묶으면 5위 동점이 25개다.

**쿼리 단위 결과 — 12건 중 검색 가능 7 / 검색 불가 3 / 번역 없음 2.**
검색 불가 3건의 원인은 전부 `foresty` 하나이고, 셋 다 숲·자연 표현이다.

```
SQ0061  비 온 뒤의 숲의 냄새    foresty + earthy          →  0개
SQ0032  숲 속에 온 듯한 향      foresty                   →  1개
SQ0073  편백나무·산내음        fresh + foresty (+direct)  →  0개
```

**그런데 같은 92개 안에 대안이 있었다.**

| 표현 | v2 원본 | 92개 안의 대안 |
|---|---:|---|
| 비 온 뒤의 숲 | 0개 | `mossy+earthy` → 4,715개 (동점 8) |
| 숲 속에 온 듯한 향 | 1개 | `mossy+green` → 1,702개 (동점 20) |
| 편백나무·산내음 | 0개 | `woody+conifer+green` → 720개 (동점 5) |

`SQ0073`의 사용자 표현은 **편백나무**이고 92개 안에 **`conifer`(침엽수, 1,828개)** 가 있다.
글자 그대로 대응하는데 v2는 `foresty`를 골랐다.

그리고 **번역이 실패하면 검색이 안 되는 게 아니라 무작위가 된다.**

```
SQ0132  포근한 느낌
  번역 실패 → direct musky 만       후보 41,154개, 5위 동점 4,010개   ← 제비뽑기
  spec §3 예시 powdery+vanilla 추가  후보  8,007개, 5위 동점     9개   ← 순위가 생김

SQ0002  시원하고 깔끔한 향
  번역 실패 → direct citrus 만      후보 59,969개, 5위 동점 17,736개
  v2 가 fresh 추가                  후보 18,826개, 5위 동점     25개
```

파싱을 믿을 수 있는지 먼저 확인했다. 재현 게이트 2개를 통과했다 —
accord 92개 `perfume_count`가 `10_accord_dictionary.csv`와 오차 0,
2개 조합 14건 AND 개수가 `10_accord_cooccurrence.csv`의 `cooccurrence_count`와 오차 0.

### 판단

**문제는 accord 목록의 크기가 아니라 매핑 단위였다.**

`spec.md` §8 남은 작업 1번의 질문("accord 92개로 부족한지")에 대한 답은 **부족하지 않다**이고,
대신 두 규칙이 필요하다.

- **한 표현은 accord 2개 이상으로 매핑한다.** 단독 매핑 금지
- **`corpus_support`로 검색이 불가능한 accord를 배제한다**

두 규칙 모두 `spec.md` §4.3의 사전이 **이미 가진 칸**으로 표현된다 —
`required`(`core`/`optional`)와 `corpus_support`. 스키마를 바꿀 필요가 없고,
canonical note를 target에 다시 넣을 필요도 없다(노트북 23의 축소 판단은 유지된다).

검색 불가 3건은 계획 §6.4의 분류로 `TARGET_SPACE_LIMITATION`이 아니라 **`MAPPING_FAILURE`** 다.
계획 §11의 REVISE 조항이 이 경우를 미리 정해뒀다 — *"`MAPPING_FAILURE`가 많음: target
vocabulary를 넓히기 전에 proposer prompt/model의 후보 탐색 문제를 우선 검토"*.

**그리고 이것이 사전이 LLM보다 확실히 나은 지점이다.** `foresty`가 향수 1개라는 것은 세상
지식이 아니라 우리 데이터 안에만 있는 사실이므로 LLM이 알 방법이 없다. 1번 측정의 문장이
그대로 적용된다 — *"이 정보는 LLM이 구조적으로 알 수 없다."*

부수적으로, 계획 §11의 GO 기준 중 *"Mixed 6개 중 Treatment 승 4개 이상"* 은 대비가 있는 Mixed
쿼리가 2개뿐이어서, *"Pure 6개 중 Strong Hit@5 4개 이상"* 은 bridge TOP5가 있는 Pure 쿼리가
1개뿐이어서 **v1 pool에서는 평가자가 무엇을 매겨도 달성할 수 없다.**

### Trade-off

- **조합을 요구하면 사전 작성 비용이 오른다.** 항목 30~50개면 accord 결정이 60~150건이 된다
- **조합은 결과를 좁힌다.** `soapy`(1,720개)를 필수로 걸면 후보가 매우 적어진다.
  `required`의 `core`/`optional`과 조건 완화로 대응하지만 완화 순서는 아직 측정되지 않았다
- **`비 온 뒤의 숲`을 `mossy+earthy`로 근사하면 `foresty`보다 의미가 넓다.**
  note를 쓰면 더 정확할 수 있지만 검증하지 않았다
- **대안 조합은 의미 판정을 받지 않았다.** *"92개 안에 쓸 수 있는 조합이 존재한다"* 까지만
  말할 수 있고 *"이것이 옳은 번역이다"* 는 말할 수 없다. AI 초안이고 팀 미승인이다
- **쿼리 12개다.** 목적 표집이며 무작위 표본이 아니다
- **점수 식이 검증되지 않았다.** target strength의 단순 합만 썼다. 실제 식이 정해지면 동점 규모가 달라진다
- **단독 금지의 임계값을 정하지 않았다.** "동점 50개 이하"는 읽기용 구분이고 GO/STOP 기준이 아니다
- 계절·시간대와 note 조건을 계산에 넣지 않았다

## 9. 전문가 자료를 찾았더니 방법론만 나오고 매핑 근거는 안 나왔다

### 문제

사전 44행의 매핑에 **의미 판정 근거가 없었다.** 검색이 되는지는 계산했지만(§8), `soapy + fresh`가
`빨래`의 *옳은* 번역인지는 계산으로 답할 수 없다. 팀에 전문 조향사가 없으므로 공개된 전문가·공식
기관 자료에서 근거를 찾기로 했다.

목표는 둘이었다. **(가)** *"정답이 없는 자연어를 어떻게 번역했는가"* 에 답할 방법론 근거,
**(나)** 개별 표현에 붙일 인용.

### 어떻게 발견했나

조사 각도 5개로 나눠 병렬 검색하고, 주장마다 3표 적대적 검증(2표 이상 반박이면 폐기)을 거쳤다.

조사 전에 **이미 가진 것을 제외**했다 — IFRA glossary 2020(파싱 완료), Michael Edwards 14계열
(팀 문서의 축), Croijmans et al. 2020(§4에 인용 중). 이 셋을 다시 찾는 데 조사를 쓰지 않았다.

### 측정

```
출처 50개 → 주장 248건 추출 → 25건을 검증 대상으로 선별 → 3표씩 판정

확정   6건
반박  19건
```

**반박률 76%다.** 검증을 절반만 돌렸을 때는 확정으로 보이던 것들이 나머지 표가 들어오며 뒤집혔다.
특히 *"학계도 평가어 60개를 ML에서 제외한다"* 가 2-0 확정에서 0-3 반박으로 바뀌었다.
부분 집계로 결론을 내면 안 된다는 사례다.

**각도별 수확**

| 각도 | 확정 |
|---|---:|
| 1. 방법론 표준 (ISO·QDA·패널 절차) | **2** |
| 2. Descriptor 어휘 원전 (Dravnieks·Pyrfume) | **2** |
| 3. 교차언어·한국어 후각어 | 1 |
| 4. 계열 분류 공식 근거 + 미정의 accord 4종 | **0** |
| 5. 장면 표현 산업 선례 (petrichor·Calone·clean linen) | **0** |

주장 248건의 키워드 집계도 같은 방향이었다. `무난한`·`고급스러운`·`도시적인`·`섹시한`·
`자연스러운`·`향긋한` 언급이 **각 0건**, 전문 용어(`탑노트`·`잔향`·`지속력`)도 **0건**이었다.

### 확정된 6건이 말하는 것

**① 우리 방법의 위치가 표준 문서 안에 있다.** ISO 13299:2016 §6.2.3은 attribute 집합이
갖춰야 할 성질을 *"non-overlapping, singular, objective, unambiguous, and referenced"* 로 적는다.
Table 1은 **"기존 용어·기준 물질 재사용"을 허용된 세 절차 중 하나(Procedure 1)로** 명시한다.
우리가 IFRA·Edwards 용어를 빌려 쓰는 것이 그 경로다.

**② 같은 표준이 그 경로의 단점도 적어뒀다.** Row 1 Disadvantages —
*"Existing terminology or reference standards may include choices that are imprecise or
inappropriate for a particular set of samples."* 그리고 기준 물질이 없으면
*"cannot be interpreted by other groups."*

**③ 교차언어 문제의 표준 해법은 "정의 + 기준 물질"이지만, 한쪽 언어에만 있는 용어는 해결되지
않고 배제됐다.** 미국·태국 간장 패널 연구에서 `cured`(태국에 없음), `roaches`(드묾),
`brown`(복합 개념)은 정의가 아니라 제외로 처리돼 최종 59개만 합의됐다.

**④⑤⑥ Dravnieks Atlas를 유료 구매 없이 확보했지만 우리에게 쓸 것이 거의 없다.**
Odeuropa가 SKOS/RDF로 무료 공개하며 descriptor 146개를 원파일로 세어 확인했다. 그중
`soapy`(des:74)와 `powdery`(des:141의 altLabel)는 인용 가능하지만,
`aquatic`·`marine`·`ozonic`·`mossy`·`tropical`·`white floral`·`musky`는
라벨 181개 + definition 9개 전체 grep에서 **0건**이다.

### 판단

**(가)는 부분 성공, (나)는 실패다.**

방법론 방어는 가능해졌다. *"검증된 정답 분류표가 없는 상태에서, ISO 13299가 허용하는
기존 용어 재사용 경로를 택했고, 표준이 명시한 그 경로의 단점을 한계로 안고 간다"* 고 말할 수 있다.

그러나 **개별 표현의 인용 근거는 하나도 못 얻었다.** 확정 6건 중 표현 단위를 다루는 것이 없다.
유일한 접점이 Dravnieks에 `soapy`·`powdery`라는 **용어가 존재한다**는 것뿐인데,
그건 *"한국어 `포근한`이 그 용어를 가리킨다"* 와 다른 진술이다.

**그래서 개별 매핑 근거는 전문가 문헌이 아니라 커뮤니티 용법 쪽에 있다.** 두 조사를 나눈 것이
결과적으로 맞았고, 전문가 조사가 담당할 수 있는 범위의 상한이 여기서 드러났다.

### 우리 매핑에 직접 걸리는 반박 3건

지지 근거만 모으면 조사가 아니므로 반박도 그대로 적는다.

**(A) SCENE 6항목이 문헌의 배제 범주에 해당한다.** `빨래`·`이불`·`호텔`·`휴양지`·`비 오는 숲`은
한국어 생활 장면 표현이고 영어 descriptor 어휘에 대응어가 없다. 간장 연구는 같은 상황에서
정의로 풀지 않고 **버렸다.** 우리는 accord 조합으로 매핑했다.

**(B) `포근한 → powdery`에 건조함이 따라온다.** Dravnieks는 powderiness를 dryness와
**한 concept으로 묶는다**(prefLabel `Dry`, altLabel `Powdery`, 원자료 표기 `DRY, POWDERY`).
유일하게 확보한 권위 자료가 그렇다. 포근함과 건조함은 같은 방향이 아니다.

**(C) ISO 의미의 `referenced`를 우리는 충족할 수 없다.** §6.2.3의 다섯 성질은 훈련된 패널이
물리적 샘플을 평가하는 상황을 전제하고, `referenced`는 **평가자에게 각 descriptor를 가르치는
물리적 기준 물질**을 뜻한다. 패널도 기준 물질도 없는 사전은 이 조건을 갖출 수 없다.
따라서 이 조항은 *"우리가 기준을 통과했다"* 가 아니라 *"기준이 무엇인지"* 에만 쓸 수 있다.

### Trade-off

- **ISO를 인용하면 우리가 못 채운 칸도 같이 드러난다.** 방법론 위치를 얻는 대신
  `referenced` 미충족이 명시적 결손이 된다. 숨기지 않는 쪽을 택했다
- **인용 위생 비용이 붙는다.** §6.2.3은 `shall`이 아니라 `The purpose is to…`이고 문서 제목이
  *General guidance*이므로 **요구사항이 아니라 목적 진술로** 인용해야 한다.
  Table 1의 `may include`도 *"반드시 안 맞는다"* 로 강화하면 안 된다
- **ISO의 `a particular set of samples`는 물리적 자극이다.** 이를 텍스트 코퍼스로 옮기는 것은
  표준이 아니라 우리 쪽 유추다. 이 유추를 표준의 진술처럼 쓰면 안 된다
- **교차언어 근거는 자기인용이다.** 리뷰 저자가 2013 원논문 공저자라 규범적 결론에
  자기홍보 성격이 있다. 리뷰의 강화된 표현이 아니라 원문 표현을 쓴다
- **간장 연구를 향수에 적용하는 것 자체가 도메인 전이다.** 감각 어휘 개발 절차가 공통이라는
  전제에 기대고 있으며 그 전제를 검증하지 않았다
- 조사 각도 4·5가 빈손이라 `aquatic`·`musky`·`tropical`·`white floral`의 공식 정의는
  **여전히 없다.** IFRA에도 없고 Dravnieks에도 없다

### 폐기한 설명

*"Dravnieks에 aquatic이 없는 것은 Calone 이후 성립한 범주라서"* — **틀렸다.**
Calone 1951은 1966년 Pfizer에서 합성돼 1985년 atlas보다 앞선다. 부재의 이유는 연대가 아니라
**범위**다. Dravnieks는 단일 냄새 분자를 고정 ballot으로 평정한 심리물리 자료이지 perfumery
accord 분류가 아니며, `gourmand`·`chypre`·`fougère`·`amber`도 똑같이 없다.

## 10. 밖에서 찾던 근거가 우리 데이터 안에 21만 건 있었다

### 문제

사전 44행의 매핑에 **의미 판정 근거가 없었다.** 매핑 28행이 전부 `status=candidate` 다.

근거를 밖에서 찾으려고 두 번 조사했고 둘 다 성적이 나빴다.

```
전문가 문헌 조사    출처 50개 · 주장 248건  →  개별 표현 근거 0건 (§9)
커뮤니티 후기 조사   에이전트 98개 · 5.6M 토큰 →  확정 3건
```

두 번째 조사가 겨우 낸 것이 **글 1~2건**이었고, 그 1건으로 사전을 고칠지 말지가 막혀 있었다.

### 어떻게 발견했나

사용자가 *"전문 조향사나 공식 기관 자료, 아니면 사용자 설문 자료가 있는지 조사해봐"* 라고 했을 때
**외부 조사를 띄우기 전에 우리 데이터를 먼저 확인**했다. `SCHEMA.md` 를 다시 읽다가 필드를 찾았다.

> `ai_summary.pros/cons` — *"Fragrantica 의 AI-요약 의견; `up_votes`/`down_votes` =
> 동의/비동의한 사용자 수"*

실물은 이렇다.

```
Givenchy / Amarige
  +142 -11   Creamy luscious tuberose
   +98 -36   Potentially overpowering and loud projection
```

**향수별 서술문 + 몇 명이 동의했는가.** 커뮤니티 조사가 찾아 헤매던 바로 그 형태다.

**왜 지금까지 안 보였나** — `perfumes.csv` 59개 컬럼에 이 필드가 없다. 서술 관련은 `description`
하나뿐이고 `ai_summary` 는 **jsonl 에만** 있다. 노트북 01~29 가 전부 CSV 로 작업했다.

`spec.md` §8 남은 작업 5번이 *"`ai_summary` 에서 추출 가능성 확인됨(40.4% 보유, heavy 18.3%)"*
이라고 적어두긴 했으나, **질감층 한 항목에만 쓰려던 메모**였고 사전 전체에 쓸 수 있다는 것은
아무도 보지 않았다.

### 측정 (노트북 30)

```
향수 131,930건 중 ai_summary 보유   12,432건 (9.4%)
서술문 총                          210,521개
accord 와 둘 다 보유                 12,432건
```

**배수**는 그 표현으로 불린 향수의 accord 보유 비율을 전체 비율로 나눈 값이다.

```
'빨래'로 불린 향수 957개 중 soapy    4.5%
전체 12,432개 중 soapy              1.3%
                                  ─────
배수 4.50
```

**먼저 통제군으로 방법을 검증했다** (`spec.md` §7.3 조건 5와 같은 취지).
표현과 무관하게 무작위 추출한 집단에서 같은 계산을 했다.

| 통제군 | 최대 배수 | 배수 1.5 이상 |
|---|---:|---:|
| n=500 | 1.17 | 0 |
| n=1,000 | 1.38 | 0 |
| n=2,500 | 1.14 | 0 |

**무작위로는 1.4배를 넘지 못한다.** 그 이상은 신호로 읽을 수 있다.
accord 92개 `perfume_count` 재현 게이트도 오차 0으로 통과했다.

**사전 28행 판정**

```
지지 14 · 약함 5 · 순환 4 · 반증(지지도 없음) 3 · 반증(전체보다 드묾) 2
```

| 표현 | accord | 해당 향수 | 배수 | 순위 | 판정 |
|---|---|---:|---:|---:|---|
| 빨래 | `soapy` | 957 | **4.50x** | 1위 | 지지 |
| 휴양지 | `coconut` | 1,211 | **5.76x** | 1위 | 지지 |
| 비 오는 숲 | `mossy` | 241 | **3.63x** | 1위 | 지지 |
| 촉촉한 | `aquatic` | 368 | **3.30x** | 1위 | 지지 |
| 깨끗한 | `soapy` | 4,044 | 2.18x | 1위 | 지지 |
| 달달 | `caramel` | 6,169 | 1.61x | 1위 | 지지 |
| 포근한 | `powdery` | 2,756 | 1.35x | **14위** | 약함 |
| 차가운 | `ozonic` | 4,010 | **0.83x** | 41위 | **반증** |
| 머스크 | `soapy` | 653 | — | — | **반증** |
| 호텔 | `soapy` | 1,163 | — | — | **반증** |

### 판단

**글 1건으로 내린 반증이 뒤집혔다.**

커뮤니티 조사는 Byredo Blanche **한 제품**에 `soapy` 가 없다는 이유로 `빨래 → soapy` 를
반증했다. 957건으로 보니 `soapy` 가 **배수 4.50 으로 1위**다. **Blanche 가 예외였다.**

그때 글 1건으로 사전을 고쳤다면 맞는 매핑을 지웠을 것이다. 판정 기준을 먼저 정하자고 하고
고치지 않은 것이 결과적으로 옳았다.

**`포근한 → powdery` 는 두 번째로 반증됐다.** 'cozy' 로 불린 향수 2,756개의 상위는
`savory` 3.72x · `nutty` 2.03x · `cacao` 2.01x · `lactonic` 2.00x 로 **고소하고 크리미한** 쪽이다.
`powdery` 는 14위 1.35배로 **통제군 최대치(1.38배)보다 낮다.** 즉 잡음 수준이다.
더쿠 후기 1건에서 `포근` 이 우디·바닐라에 붙었던 것과 같은 방향이며, 독립적으로 두 번 나왔다.

**매핑을 포기한 판단이 데이터로 지지됐다.** `무난한` 은 향수 6,217개가 있는데 최대 배수 1.30,
`고급스러운` 은 6,966개에 1.38이다. 둘 다 **통제군 수준**이고 어떤 accord 로도 수렴하지 않는다.
팀 문서의 *"(매핑 근거 미확보)"* 와 우리 `NO_MAPPING` 6행이 옳았다.

**순환을 자동으로 검출하게 만들었다.** 검색어가 accord 이름과 같으면 동어반복이다.
`휴양지 → tropical` 은 배수 5.74로 높지만 검색어가 `tropical` 이라 신호로 읽지 않는다.
`머스크 → musky`, `달달 → sweet` 도 같은 이유로 걸렸다.

### Trade-off

- **전문 조향사·공식 기관 근거가 아니다.** Fragrantica 의 AI 가 사용자 리뷰를 요약한 것이다.
  투표로 검증된 대중 의견이라는 점이 커뮤니티 글 1~2건보다 나을 뿐이다
- **커버리지가 심하게 치우쳐 있다.** `ai_summary` 보유 향수의 평가자 수 중앙값은 **628명**,
  미보유는 **9명**이다. **70배 차이**다. 이 신호는 대중적으로 많이 쓰이는 향수에서의 관계이고
  나머지 119,498건에는 보증할 수 없다
- **영어 서술이다.** `포근한 = cozy` 라는 번역 가정이 한 단계 들어간다. 일반 번역이라
  향 도메인 추론보다 약한 가정이지만 가정은 가정이다
- **출처가 Fragrantica 다.** `spec.md` §8 의 `ai-train=no` · EU 권리유보 문제가 그대로 적용된다.
  서비스에 쓰려면 그 판단이 선행돼야 한다
- **부분 문자열 검색의 잡음을 제거하지 않았다.** `이불` 에서 `caramel` 7.36배가 1위로 나왔는데
  `bedding|cotton|blanket` 검색이 `cotton candy` 를 잡은 것으로 보인다. 해당 향수도 112개뿐이다
- **투표수를 쓰지 않았다.** 서술문의 존재 여부만 봤다. `up_votes` 를 가중하면 결과가 달라질 수 있다
- **동반 출현이지 인과가 아니다.** 배수가 높다는 것은 같이 나타나는 일이 잦다는 뜻이다
- **6개 표현은 노트북 작성 전에 결과를 봤다** (`포근한`·`빨래`·`깨끗한`·`휴양지`·`무난한`·`고급스러운`).
  탐색 때 쓴 영어 대응어를 바꾸지 않았고 보지 않은 표현도 전부 포함했다.
  노트북 사전 등록의 `known_deviation` 에 기록돼 있다
