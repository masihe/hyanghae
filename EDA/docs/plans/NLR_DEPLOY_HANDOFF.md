## 1. 이 서버가 무엇인가

사용자가 한국어 문장으로 원하는 향을 쓰면 향수 5개와 추천 근거를 돌려줍니다.
Spring 이 내부에서 호출하는 API 이고, 브라우저가 직접 부르지 않습니다.

```
[브라우저] → [Nginx] → [Spring] → [AI 서버] → (GMS API)
```

**가벼운 이유** — DB 에 접속하지 않습니다. 마이그레이션도 초기 데이터 적재도 없습니다.
필요한 데이터가 전부 저장소 안에 파일로 들어 있습니다(`ai/data/`, 합계 약 5MB).
컨테이너만 뜨면 바로 동작합니다.

기동할 때 그 파일을 읽어 메모리에 129,161 × 92 행렬(45MB + 11MB)을 만듭니다.
요청마다 만들지 않고 기동 시 한 번만 만듭니다 — 인프라가 손댈 것은 없고
**메모리 산정에만 영향**을 줍니다.

## 2. 컨테이너로 올릴 때

### Dockerfile 은 `ai/Dockerfile` 에 있습니다

```bash
docker build --tag hyanghae-ai:latest ai
docker run --rm -p 8000:8000 -e GMS_API_KEY=... hyanghae-ai:latest
```

> ⚠ **AI 쪽에서 이미지를 실제로 빌드해 보지 못했습니다.** 작업 환경에 Docker 가 없습니다.
> 첫 빌드는 인프라 쪽에서 돌려 주셔야 하고, 실패하면 알려 주시면 고치겠습니다.
> 빌드 없이 확인한 것은 「부록」에 적었습니다.

```
베이스      python:3.11-slim   (백엔드와 달리 빌드 단계가 없습니다)
설치        pip install -r requirements.txt    컴파일 없음. 휠로 설치됩니다
빌드 컨텍스트  ai/ 에서 5.0MB · 파일 20개   (venv 159MB · delivery 6.1MB 는 .dockerignore 로 제외)
사용자      nlr (비특권). backend/Dockerfile 과 같은 방식
포트        8000 (컨테이너 내부 고정)
실행        uvicorn server:app --host 0.0.0.0 --port 8000
헬스체크    이미지에 내장돼 있습니다. `docker ps` 의 STATUS 에 health 가 보입니다
```

`.dockerignore` 가 **`logs/` 를 제외**합니다. 사용자 원문이 이미지에 구워지지 않게 하려는 것이니
빼지 마십시오.

### 워커 수 — 여기만 주의하시면 됩니다

**`--workers N` 을 주면 메모리가 그 배수로 늘어납니다.**
워커마다 162MB 짜리 행렬을 따로 만듭니다. 4개면 약 650MB 입니다.

그리고 워커를 늘려서 얻을 것이 별로 없습니다. 요청 시간의 대부분은 **GMS 응답을 기다리는
시간**(중앙 1.5초)이지 계산이 아닙니다. 검색 자체는 **3.4ms** 입니다 [측정].
기다리는 동안 CPU 는 놀고 있고, 같은 워커 안에서 다른 요청을 처리할 수 있습니다
(FastAPI 가 동기 함수를 스레드풀에서 돌립니다).

**워커 1개로 시작하시고, 실제로 부족해지면 그때 늘리는 것을 권합니다** [추정].

## 3. 환경변수

| 이름 | 필요 | 값 | 비고 |
|---|---|---|---|
| **`GMS_API_KEY`** | 사실상 필수 | 배포 디렉터리 `.env` 에 **이미 있는 값** | 없어도 서버는 뜹니다. 아래 참고 |
| `GMS_MODEL` | **넣지 마십시오** | — | 🚨 아래 경고 |
| `GMS_ENDPOINT` | 불필요 | 코드에 기본값 | 건드릴 일 없습니다 |
| `NLR_LOG_PATH` | 권장 | 볼륨 경로 | 5장 참고 |
| `NLR_LEXICON_PATH` | 불필요 | | 사전 버전 비교용 |
| `NLR_PERFUMES_PATH` | 불필요 | | |

### 키를 새로 발급받을 필요가 없습니다

`GMS_API_KEY` 는 백엔드의 후기 요약 배치가 이미 쓰고 있어서
**`/home/ubuntu/hyanghae/.env` 에 들어 있습니다**(`application-prod.yaml` 이 참조).
같은 값을 AI 컨테이너에도 넣어 주시면 됩니다.

### 🚨 `GMS_MODEL` 은 넣지 마십시오 — 백엔드와 값이 다릅니다

```
백엔드(후기 요약)   기본값 gpt-5-nano      application-prod.yaml
AI 서버(향 조건)    기본값 gpt-5.4-nano    llm_stage1.py
```

같은 `.env` 를 두 컨테이너가 공유하는 구조라, `GMS_MODEL` 을 하나 정해 넣으면
**둘 중 하나가 의도하지 않은 모델로 돕니다.** 둘 다 코드에 기본값이 있으므로
**아예 넣지 않는 것이 안전합니다.** 꼭 넣어야 한다면 컨테이너별로 다른 값을 주십시오.

### 키가 없으면 — 백엔드와 반대로 동작합니다

백엔드는 키 없이 켜면 애플리케이션이 아예 뜨지 않도록 만들어 두었습니다.
**AI 서버는 반대로 정상 기동합니다.** LLM 이 죽어도 서비스를 내리지 않는 것이 설계라서입니다.

| | 문장에서 향 조건을 뽑는 비율 |
|---|---|
| 키 있음 | **86.7%** |
| 키 없음 | **75.5%** |

합성 평가셋 600문장 기준 [측정]. **에러가 나지 않아 응답만 봐서는 구분이 안 됩니다.**
그래서 확인 방법을 두 개 넣어 두었습니다. **배포 후 한 번 확인해 주십시오.**

```bash
curl http://<ai-host>:8000/health
# {"status":"ok","perfumes":129161,"accords":92,"llm":true}
#                                              ^^^^^^^^^^^ 이 칸이 true 여야 합니다
```

```
기동 로그
INFO:llm_stage1:stage1 프롬프트 적재 stage1_prompt_v1.txt sha256=4f0a368d98b41338
INFO:server:①단계 LLM 구조화 켜짐 (model=gpt-5.4-nano prompt=4f0a368d98b41338)
```

## 4. 네트워크

### 인바운드 — 외부에 열면 안 됩니다

```
[브라우저] → [Nginx/Spring] → [AI 서버]     이 경로만
[브라우저] ─────────────────→ [AI 서버]     ✗ 막아야 합니다
```

**이 서버에는 인증도 호출량 제한도 없습니다.** 둘 다 Spring 이 맡기로 되어 있습니다
(`ai/docs/nlr_api_contract.md`: *"내부 API. 외부에 열지 않는다"*).

외부에 열리면 누구나 팀의 GMS 키로 LLM 을 호출하게 만들 수 있습니다.

**같은 compose 네트워크에 두고 호스트로 포트를 publish 하지 않는 것**이 가장 간단합니다.
백엔드는 `http://<서비스이름>:8000` 으로 부르면 됩니다.

### 아웃바운드 — 2026-09-15 에 새로 생긴 요구사항입니다 ★

```
[AI 서버] → https://gms.ssafy.io   (HTTPS / 443)
```

**이 서버는 어제까지 인터넷이 전혀 필요 없었습니다.** 오늘 LLM 호출을 붙이면서
처음으로 외부로 나가게 되었습니다.

보안 그룹이나 방화벽이 아웃바운드를 막고 있으면 **에러 없이 조용히 75.5% 로 떨어집니다**
(5초 타임아웃 뒤 사전 매칭으로 내려갑니다). 서버 로그에는 남습니다.

**이 항목을 모르고 배포하면 원인을 찾기 매우 어렵습니다.**

## 5. 볼륨 — 개인정보가 들어갑니다

```
컨테이너 안   /app/logs/unmatched.jsonl      (NLR_LOG_PATH 로 경로 변경 가능)
```

사전이 알아듣지 못한 표현을 기록해 사전을 키우는 근거로 씁니다.
**여기에 사용자가 입력한 원문이 들어갑니다.** 실사용자 설문에서 건강·신분 관련 서술이
있었습니다.

| | |
|---|---|
| 필요한 것 | 컨테이너를 다시 띄워도 남도록 **볼륨 1개** |
| 크기 | 작습니다. 한 줄에 수백 바이트 |
| **주의** | **백업을 외부로 보내거나 로그 수집기로 퍼가기 전에 AI 쪽에 확인해 주십시오** |
| 보관 | 30일 지난 원문을 비우는 함수가 있습니다. **자동 실행은 아직 없습니다** [미확인] |

### 쓰기 권한이 없으면 — 요청은 살고 기록만 사라집니다

| | |
|---|---|
| 없으면 | **서버는 정상 동작합니다.** 추천도 200 으로 나갑니다. 기록만 사라집니다 [측정] |
| 확인 방법 | 서버 로그에 `ERROR ... 미매칭 로그를 쓰지 못했다. 추천은 그대로 돌려준다` |

> 2026-09-15 이전에는 **쓰기가 막히면 요청마다 500 이 났습니다.** 고쳤습니다.
> 지금은 원인을 `ERROR` 로 남기고 추천은 그대로 돌려줍니다. 로그는 사전을 키우는
> 재료이지 응답에 필요한 것이 아니라서입니다.

그래도 **기록이 남는 편이 낫습니다.** 이게 사전을 키울 유일한 단서입니다.

```
Dockerfile 이 /app/logs 를 만들고 컨테이너 사용자(nlr)에게 소유권을 줍니다.

named volume 을 붙이면   Docker 가 그 소유권을 볼륨에 복사합니다 -> 그대로 됩니다
bind mount 를 붙이면     호스트 디렉터리 소유자가 그대로 쓰입니다
                         -> 호스트 디렉터리를 컨테이너의 nlr 이 쓸 수 있게 맞춰 주십시오
                            안 맞으면 조용히 기록만 안 남습니다
```

**named volume 을 권합니다** [추정]. bind mount 를 쓰셔야 하면 알려 주십시오 —
UID 를 고정해 드리는 편이 안전합니다.

## 6. 헬스체크

```
GET /health

200  {"status":"ok","perfumes":129161,"accords":92,"llm":true}
503  {"code":"NLR_NOT_READY","message":"데이터를 아직 적재하지 못했습니다."}
```

## 7. Jenkinsfile 에 필요한 것 — AI 쪽이 건드릴 수 없는 부분입니다

`Jenkinsfile` 은 저장소 루트에 있고, AI 는 `ai/` 밖을 건드리지 않기로 되어 있습니다.
백엔드와 같은 모양으로 네 군데가 필요합니다.

```
1. Docker Image Build   docker build --tag hyanghae-ai:latest ai
2. Deploy               서버의 compose.yaml 에 ai 서비스 추가
                        (compose.yaml 이 서버에 있어 AI 쪽에서는 볼 수 없습니다)
3. Health Check         curl --fail --retry ... http://127.0.0.1:<포트>/health
4. .env                 GMS_API_KEY 는 이미 있음. GMS_MODEL 은 넣지 말 것
```

**포트를 하나 배정해 주셔야 합니다.** 백엔드가 호스트 8081 을 쓰고 있습니다.

## 10. 인수인계 체크리스트

```
[ ] docker build --tag hyanghae-ai:latest ai  가 통과하는지 확인 (첫 빌드)
[ ] AI 컨테이너용 포트 배정
[ ] compose.yaml 에 ai 서비스 추가 (호스트로 포트 publish 하지 않음)
[ ] .env 의 GMS_API_KEY 를 ai 컨테이너에 전달
[ ] .env 에 GMS_MODEL 을 넣지 않았는지 확인
[ ] 아웃바운드 https://gms.ssafy.io (443) 허용
[ ] 로그 볼륨 1개 연결 — named volume 권장. bind mount 면 소유권 확인
[ ] Jenkinsfile 에 이미지 빌드 · 배포 · 헬스체크 추가
[ ] 배포 후 /health 의 "llm" 이 true 인지 확인
[ ] 배포 후 요청을 한 번 보내 200 이 오는지 확인
[ ] 서버 로그에 "미매칭 로그를 쓰지 못했다" 가 없는지 확인 (있으면 볼륨 권한 문제)
[ ] AI 서버가 외부에서 직접 접근되지 않는지 확인
```

**컨테이너에서 다시 재야 합니다.** Linux 와 Windows 의 메모리 측정 방식이 다르고,
이미지 베이스에 따라서도 달라집니다.

### Docker 없이 확인한 것 / 확인하지 못한 것

Docker 가 없는 환경이라 **이미지를 빌드하지 못했습니다.** 대신 아래를 확인했습니다.

| 확인한 것 | 방법 | 결과 |
|---|---|---|
| 헬스체크 명령 | 서버를 띄우고 그대로 실행 | 서버 없음 → exit 1 · 정상 → exit 0 |
| 기동 중 동작 | uvicorn 이 소켓을 먼저 열어 연결이 대기함 | `timeout=5s` 가 2.4초 기동을 덮습니다 |
| 빌드 컨텍스트 | `.dockerignore` 규칙을 적용해 계산 | **5.0MB · 파일 20개** (venv 159MB · delivery 6.1MB 제외됨) |
| 로그 권한 실패 | 쓸 수 없는 경로로 요청 | **200 + ERROR 로그** (고치기 전에는 500 이었습니다) |
| 서버 실행 | uvicorn 으로 직접 기동 후 요청 | 정상 |

| 확인하지 못한 것 |
|---|
| `docker build` 가 통과하는지 |
| `python:3.11-slim` 에서 `groupadd`/`useradd` 가 되는지 (표준 이미지라 될 것으로 보지만 확인 못 했습니다) |
| Linux 컨테이너에서의 메모리·기동 시간 |
| `pip install` 이 휠로만 끝나는지 (컴파일러가 필요하면 빌드가 실패합니다) |
