## 1. 왜 만드는가

`spec.md` §7.2가 정리한 대로 현재 평가 자산은 **조건 추출**만 채점한다.
*"이 문장에 이 향수가 맞다"* 는 데이터가 **하나도 없다.**

그래서 다음을 판정할 수 없다.

- 하드 AND 필터와 가중 점수 중 어느 쪽이 나은가 (`DECISIONS.md` N2 재검토)
- `avoid`가 사전 항목 전체를 쓸 것인가 (`spec.md` §8 11번)
- 조건 두 갈래가 동시에 걸릴 때 (§8 12번)

**채점표가 설계보다 먼저 있어야 한다.** 노트북 22가 반대로 했다 — 시스템 v1을 돌리고
그 결과에 판정표를 맞춰 만들었는데 v1이 12건 중 7건 스키마 실패라 70건이 못 쓰게 됐다.

## 2. 이 데이터를 뭐라고 부르는가

**이름: 합성 평가셋 (synthetic eval set).**

| 쓸 수 있는 말 | 쓰면 안 되는 말 |
|---|---|
| 설계 비교용 **상대** 지표 | "추천 정확도 XX%" |
| **회귀 테스트** — 코드 변경이 깨뜨리는지 | "실사용 성능" |
| **하한선** — 못 넘으면 확실히 고장 | "검증 완료" |

*"통과 못 하면 확실히 문제"* 는 말할 수 있고 *"통과했으니 잘 작동한다"* 는 말할 수 없다.

실사용 성능은 설문 143건 라벨링이 나와야 잴 수 있고 그건 시스템이 나온 뒤다.
**이 데이터가 그것을 대체하지 않는다.**

### 합성 평가셋과 설문은 역할이 다르다 — 서로의 결손을 메운다

AI에게 향수 하나를 주고 **사용자가 쓸 법한 문장**을 만들게 했다. 그래서 정답 향수가
공짜로 붙는다. 대신 그 문장에는 **현실의 노이즈가 없다.** 가격·건강·개인화처럼
사람이 실제로 섞어 쓰는 조건이 빠진다 (실측은 §12).

그 칸은 **실제 일반인에게 받은 설문 155건**이 메운다. 설문은 사람이 쓴 문장이라
노이즈가 그대로 있지만 정답 향수가 없다.

| | 합성 평가셋 | 설문 155 |
|---|---|---|
| 문장 출처 | AI 역생성 | 실제 사용자 |
| 정답 향수 | **있다** (정의상) | 없다 |
| 현실 노이즈 | **없다** | 있다 |
| 순환 | 남아 있다 (§5) | 없다 |
| 답하는 질문 | *"이런 향수를 찾아냈나"* | *"이 문장의 조건을 제대로 뽑았나"* |

**같은 지표로 메우는 것이 아니다.** 설문에는 정답 향수가 없으므로 검색 품질을
직접 재지 못한다. 두 데이터가 **서로 다른 질문**에 답하고, 합쳐야 한 바퀴가 돈다.

이 구조는 새로 만든 것이 아니라 `spec.md` §7.2 가 golden 200 과 설문 155 에 대해
이미 정한 역할 분담을 **한 칸 더 채운 것**이다.

```
golden 200   조건 추출 회귀 테스트      라벨 있음 · 팀원 작성 · 짧고 단순
합성 600     검색 회귀 테스트           정답 있음 · AI 작성 · 노이즈 없음   ← 이번에 추가
설문 155     실사용 성능 (라벨링 필요)   라벨 없음 · 사람 작성 · 노이즈 있음
```

## 3. 정답을 향수 1개로 두지 않는다 — 측정 근거

131,930개 전수. accord 92개 `perfume_count` 재현 게이트 오차 0.

| 향수를 기술하는 방식 | 그 조합이 유일한 비율 | 같은 조합 공유 (중앙값) |
|---|---:|---:|
| accord 8개 전부 | 48.0% | 2개 |
| **상위 3개 accord** | **2.1%** | **188개** |

사용자는 accord 8개를 다 말하지 않는다. 설문 실측 평균 조건 수가 **2.7개**다.
그 수준에서 정답은 1개가 아니라 수백 개다.

**그래서 채점을 "이 향수가 나왔나"가 아니라 "이런 향수가 나왔나"로 한다.**

## 4. 고정 — 모집단과 표집

| 항목 | 값 | 근거 |
|---|---|---|
| 후보 풀 | `people >= 500` → **7,823개** | MAP `D3`이 지도 후보 풀에 쓴 기준. 무작위로 뽑으면 평가자 9명짜리 무명 향수가 대부분이 된다 |

| 규모 | **향수 100개 × 문장 3개 = 갈래당 300문장** | 노트북 22가 12건이라 결론을 못 냈다. golden set 200건과 비교 가능한 규모 |
| 배치 | **25개씩 4배치. 배치마다 독립적으로 계열 균형** | 수작업 생성이므로 일부 배치만 해도 균형이 유지되게 한다 |
| 시드 | `42` | 프로젝트 관행 |

**감수하는 것 — 인기 향수 편향.** `DECISIONS.md` N4가 `ai_summary`에서 겪은 것과 같다.
*"대중적 향수에서의 관계이고 나머지에는 보증할 수 없다"* 를 결과에 그대로 적는다.

## 5. 고정 — 두 갈래와 순환

### 순환이 없는 갈래는 이 데이터로 만들 수 없다

문장을 향수에서 역생성하는 이상, 생성에 쓴 표현과 검색에 쓰는 표현이 겹친다.
**없앨 수 없으므로 크기를 잰다.** 두 갈래의 순환 경로를 다르게 만들고 점수 차를 본다.

| 갈래 | LLM에게 주는 것 | 순환 경로 |
|---|---|---|
| **A** | 상위 **5개** accord + strength | **검색 인덱스와 순환** — 시스템이 검색하는 바로 그 표현 |
| **B** | `ai_summary` 서술문 (up_votes 상위 pros 6 + cons 3) | **사전 근거와 순환** — N4가 사전 의미 판정에 쓴 데이터 |

**갈래 B도 순환이 없는 것이 아니다.** 종류가 다를 뿐이다. 그렇게 보고한다.

`A − B` 점수 차 = 검색 인덱스 직결 순환이 점수를 부풀린 크기.

### `description`을 쓰지 않는 이유

후보 풀에서 실물을 확인한 결과 `description`은 감상문이 아니라 **정보표**다.

```
<이름> by <브랜드> is a <계열> fragrance for <성별>.
<이름> was launched in <연도>.
The nose behind this fragrance is <조향사>.
Top notes are Bergamot, Verbena...; middle notes are...; base notes are...
```

후보 풀의 **84.8%**가 note 목록 문구를 갖고 있고 향수 이름이 반복된다.
note는 검색에 쓰이는 표현이므로 순환이 끊기지 않는다. **기각.**

### `ai_summary` 커버리지

| 모집단 | `ai_summary` 보유 |
|---|---:|
| 전체 131,930개 | 12,432개 (9.4%) |
| **후보 풀 7,823개** | **7,414개 (94.8%)** |

서술문 개수 중앙값 15개(최소 4 / 최대 24). `up_votes` 상위로 잘라 쓴다.
N4가 *"투표수를 쓰지 않았다"* 를 한계로 남겼으므로 여기서는 쓰고, 썼다고 적는다.

## 6. 고정 — 생성 규칙

LLM은 **사람이 GPT에 직접 업로드해서** 돌린다. API를 쓰지 않는다.

```
1  한국어 문장으로 쓴다
2  accord 영어 이름을 문장에 그대로 쓰지 않는다      ← 쓰면 사전이 할 일이 없어진다
3  향수 이름·브랜드·조향사·연도를 쓰지 않는다         ← 이름으로 찾는 건 검색 테스트가 아니다
4  실사용 분포에 맞춘다 — 길이 70자 내외, 조건 2~3개
5  한 향수당 서로 다른 문장 3개
```

**4번을 지시하지 않으면 짧고 단순한 문장이 나온다.** golden set 200이 실사용과 달라
위상이 내려간 일(§7.2)이 반복된다.

### 재생성 규칙

- **2·3번 위반과 형식 오류만 재생성한다.** 자동 검출한다
- **문장이 마음에 안 든다는 이유로는 재생성하지 않는다**
- 파일럿 플랜 §10의 *"schema/API 실패 재시도 외에 재호출하지 않는다"* 를 따른다

### 기록할 것 (사람이 채운다)

업로드해서 생성한 뒤 `32_evalset_run_log.md`에 적는다.

```
사용한 모델 이름과 버전
생성 일시
배치별 재생성 횟수와 사유
프롬프트를 그대로 썼는지, 고쳤다면 무엇을
```

**모델과 온도를 통제할 수 없다는 것이 이 방식의 한계다.** 적어두고 결과에 병기한다.

## 7. 고정 — 채점 기준

### 조건 집합 C

**C = 그 향수의 strength 상위 3개 accord.**

동점이면 accord 이름 오름차순으로 자른다(결정적 tie-break).

### 주 지표 — Condition Precision@5

> 시스템이 낸 상위 5개 중 **C를 전부 가진** 향수가 몇 개인가

느슨한 정의(**C 중 2개 이상**)도 같이 계산해 나란히 보고한다. 계산 비용이 같다.

### 보조 지표 1 — 원본 향수 Recall@5 · MRR

**반드시 랜덤 기대값과 함께 적는다.**

```
기대값 = 5 / (C 를 전부 만족하는 향수 수)
```

이 바닥선 없이 *"30% 나왔다"* 고 하면 좋은 건지 알 수 없다.

### 보조 지표 2 — 갈래 A 점수 − 갈래 B 점수

검색 인덱스 직결 순환의 크기.

### 진단 지표 (합격 판정에 쓰지 않는다)

- 상위 5위 동점 수
- 조건이 하나도 안 잡힌 문장 비율
- 완화 단계 발동 횟수
- **생성 문장과 설문 155건의 분포 비교** — 길이 · 조건 수 · 전문 용어 비율

마지막 항목이 이 평가셋의 신뢰도를 말한다. 안 닮았으면 안 닮았다고 적는다.

## 12. 이 평가셋이 답하지 못하는 것

미리 적어둔다. 결과가 나온 뒤에 덧붙이면 변명이 된다.

1. **실사용 성능을 말하지 못한다.** 합성 문장이고 인기 향수에 치우쳐 있다
2. **순환이 남아 있다.** 갈래 A는 검색 인덱스와, 갈래 B는 사전 근거와 겹친다
3. **모델을 통제하지 못한다.** 사람이 GPT UI에서 돌리므로 온도·버전이 고정되지 않는다
4. **사전의 기여를 재기에 불리하다.** 사전의 값어치는 LLM 상식과 다른 지점
   (`머스크`의 한국어 드리프트, `foresty`의 코퍼스 1건)인데 LLM이 만든 문장에는
   그런 경우가 잘 나오지 않고, 나와도 사전이 감점될 수 있다
5. **note를 쓰지 않는다.** 실사용자의 18.1%가 전문 용어를 쓰는데 이번 갈래 A는 accord만 준다.
   필요하면 변형으로 추가한다

## 12-1. 생성 뒤 실측 — 무엇이 닮았고 무엇이 다른가 (노트북 33)

**결과를 채점하기 전에 기록한다.** 점수를 본 뒤에 적으면 변명이 된다.

먼저 `spec.md` §7.2 의 기록값을 재현해 측정 방식이 같은지 확인했다 — **4개 전부 일치.**

| 집단 | 건수 | 평균 길이 | 길이 중앙값 | 전문 용어 | 절 개수(대리) |
|---|---:|---:|---:|---:|---:|
| golden 200 (팀원) | 201 | 29.6자 | 29 | 5.5% | 1.25 |
| **생성 갈래 A** | 300 | 56.7자 | **57** | **0.0%** | 2.00 |
| **생성 갈래 B** | 300 | 58.4자 | **58** | **0.0%** | 2.02 |
| 설문 155 (실사용) | 155 | 70.9자 | **57** | 18.1% | 2.72 |

**닮은 것 — 길이와 구조.** golden 200 이 29자 / 1.25절로 실사용의 절반도 안 됐던 문제를
넘었다. 길이 중앙값이 설문과 같다. 설문의 평균이 71자로 높은 것은 긴 꼬리(최대 600자)
때문이다.

**다른 것 — 어휘와 현실 노이즈.**

| | 생성 600건 | 설문 155건 |
|---|---:|---:|
| 전문 용어 (잔향·지속력·노트…) | **0건 (0.0%)** | 28건 (18.1%) |
| 가격 조건 | **2건 (0.3%)** | 25건 (16.1%) |
| 건강 조건 (두통·민감…) | **0건** | 1건 |
| 개인화 요청 (*"나에게 어울리는"*) | **0건** | 10건 (6.5%) |

**전문 용어 0%는 설계의 결과다.** §6 규칙 2 가 영어 향 용어를 막았고 갈래 A 에 note 를
주지 않기로 했다. 그 대가로 **사전의 우선순위 1번인 전문 용어 10행이 이 평가셋의
사각지대**가 된다 (`DECISIONS.md` N1 이 18.1% 를 근거로 1순위에 올린 항목들이다).

**이 결손은 §2의 역할 분담으로 메운다.** 노이즈가 있는 문장은 설문 155건이 담당한다.
다만 설문에는 정답 향수가 없으므로 **같은 지표로 메우는 것이 아니다.**

전문 용어를 검색 채점까지 넣으려면 **평가셋 v2** 가 필요하고 그것은 별건이다.
