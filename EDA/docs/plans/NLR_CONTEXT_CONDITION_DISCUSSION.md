## 1. 왜 바뀌나 — 한 문단

지금까지 엔진은 사용자의 말에서 **향만** 읽었습니다.

```
'빨래 냄새 나는 향수'  ->  soapy · fresh 를 가진 향수
                      이유: "빨래 라고 하셔서 soapy 를 골랐어요"
```

그런데 원본 데이터에는 향 말고도 **이 향수가 중성적인지 · 여름에 어울리는지 · 밤에
어울리는지 · 어떤 노트가 들었는지**가 있습니다. 엔진이 그걸 안 쓰고 있었습니다.

```
'중성적인 향수 추천해줘'  ->  (전) 결과 0건
                       ->  (후) 중성적이라고 투표된 향수 5개
```

**이유를 담는 칸이 향 하나뿐이라, 칸을 하나 더 만들었습니다.** 그게 2장입니다.
그리고 **이 경우에 화면 문구를 잘못 쓰면 거짓말이 됩니다.** 그게 3장입니다.

## 2. 백엔드에게 — 받는 것이 하나 늘어납니다

### 2-1. 무엇이 늘어나나

`POST /nlr/recommend` 응답 **최상위**에 `matchedData` 배열이 생깁니다.

```json
{
  "status": "OK_RELAXED",
  "conditions": { "core": [], "avoid": [], "matchedExpressions": [], "source": "..." },

  "matchedData": [
    { "field": "gender", "value": "unisex", "label": "중성적인",
      "from": null, "tier": "DATA" }
  ],

  "results": [ { "fragranticaId": 1234, "name": "...", "matched": [] } ]
}
```

| 칸 | 뜻 |
|---|---|
| `field` | `gender` / `season` / `daypart` / `note` |
| `value` | 데이터 쪽 값 (`unisex` · `summer` · `night` · `mimosa`). **내부 값이라 화면에 그대로 나가면 안 맞습니다** — `label` 을 쓰시면 됩니다 |
| `label` | **화면에 그대로 쓸 한국어** (`중성적인` · `여름에 어울리는` · `밤에 어울리는`). 노트는 사용자가 쓴 말 그대로 |
| `from` | 노트만 채웁니다. 성별·계절·낮밤은 `null` [확인] ①단계가 값만 주고 원문의 어느 글자에서 왔는지는 안 줍니다 |
| `tier` | 항상 `DATA`. Fragrantica 사용자 투표에서 직접 온 값이라 기존 `VERIFIED`/`TEAM`/`LLM` 어디에도 안 맞습니다 |

조건을 안 걸었으면 `[]` 입니다. **기존 요청은 대부분 `[]` 입니다.**

### 2-2. 영향을 받는 자리 [제안]

계약서 「백엔드가 하는 변환」 ②가 *"`matched` 를 `from` 별로 묶어 `reasons` 를 만든다"*
인데, **`matchedData` 를 안 읽으면 향 조건 없이 고른 추천에 이유가 하나도 안 붙습니다.**
그래서 함께 넣는 것을 제안드립니다 — **다른 방법이 더 맞다면 그쪽으로 해 주세요.**

```
전   reasons  <-  matched (accord 근거)
후   reasons  <-  matched (accord 근거)  +  matchedData (성별·계절·낮밤·노트 근거)
```

`matchedData` 는 `label` 이 이미 한국어라 **`matched` 와 달리 번역이 필요 없습니다.**
(계약서가 *"`soapy` 를 사용자에게 보여줄 수 없다"* 로 막아 둔 그 문제가 여기엔 없습니다.)

### 2-3. 안 바뀌는 것 — **여기는 안 보셔도 됩니다**

```
status 네 값        OK · OK_RELAXED · NO_CONDITION · NO_RESULT   그대로
matched[]          한 글자도 안 바뀝니다
conditions         그대로
unmatched[]        그대로
조건이 하나도 없을 때   여전히 NO_CONDITION · results []
                  계약서의 "인기 향수를 대신 보여주면 안 된다" 는 그대로 지켜집니다
```

### 2-4. [정해 주세요] 둘

**① `matchedData` 를 최상위로 받으시겠습니까, 결과별로 받으시겠습니까?**

```
최상위 (지금 구현)   배열 하나. 추천 5개에 똑같이 적용되므로 반복이 없습니다
                  화면에서 "중성적인 향수 중에서 골랐어요" 를 목록 위 한 줄로 쓰기 좋습니다

결과별             results[].matchedData 로 향수마다 넣습니다
                  같은 내용이 다섯 번 들어가지만, 향수 카드마다 이유를 붙이는
                  화면이라면 이쪽이 다루기 쉽습니다
```

**AI 추천은 최상위입니다.** 다만 화면 설계에 달린 문제라 프론트와 함께 보시는 게
맞다고 봅니다. 결과별이 낫다면 AI 쪽에서 바꾸겠습니다 — 코드 몇 줄입니다.

**② 이 근거를 `nlr_*` 표에 남기시겠습니까?**

`S15P21E203-325` 에서 여섯 칸을 추가한 선례가 있습니다. 남기면 *"성별·계절만으로 고른
요청이 실사용에서 얼마나 되나"* 를 나중에 셀 수 있습니다. **급하지 않습니다** —
지금 안 남겨도 기능은 돕니다.

## 3. 프론트에게 — **문구를 잘못 쓰면 거짓말이 됩니다**

### 3-1. 도서관에서 생긴 일

도서관에서 *"재밌는 책 추천해줘"* 라고 하면 사서는 장르도 취향도 모릅니다.
그래서 **많이 빌려 간 책**을 줍니다.

```
"재밌는 책으로 골랐어요"                          <- 거짓말입니다
"많이 빌려 가신 책이에요. 어떤 장르 좋아하시는지 알려주시면 더 잘 찾아드릴게요"
```

`중성적인 향수 추천해줘` 가 정확히 이 경우입니다.

```
후보를 21,341개로 좁힌 근거    **있습니다** — 중성적이라고 투표된 향수 [측정]
그 안에서 5개를 고른 근거      **없습니다** — 평가자가 많은 순입니다 [확인]
```

향 조건이 하나도 없으니 **향으로 줄을 세울 수가 없습니다.** 5위와 점수가 같은 향수가
21,341개입니다 [측정 · `tieAtLast`].

### 3-2. 이 경우를 어떻게 아나

```
conditions.core 가 비어 있다   **그리고**   결과가 있다   ->   향 조건 없이 고른 경우
```

`matchedData` 가 비어 있지 않은 것으로도 볼 수 있습니다. 어느 쪽이든 됩니다.
백엔드가 플래그로 만들어 주시면 더 편합니다 — **[정해 주세요]**.

### 3-3. 어디가 위험한가 — **문구는 프론트가 정하시면 됩니다**

아래는 **정답이 아니라 위험을 보여드리는 예시**입니다. 말투와 표현은 프론트 판단입니다.

```
위험   "중성적인 향수를 찾았어요"
       향을 보고 고른 것처럼 읽힙니다. 실제로는 인기순입니다

위험   "여성스러운 향수를 골랐어요"
       사용자가 '귀엽고 여성스러운 디저트 같은 향' 이라고 했다면
       **디저트·달콤함을 고려했다고 믿습니다.** 고려 안 했습니다

[제안] "중성적인 향수 중에서 평가가 많은 순으로 골랐어요.
       어떤 향을 원하시는지 한 가지만 더 말씀해 주시면 더 잘 찾아드릴게요"
       한 것과 안 한 것이 둘 다 들어 있습니다
```

**지켜야 할 것은 이 문구가 아니라 두 가지뿐입니다.**

```
1  향으로 골랐다고 읽히지 않게 한다
2  사용자가 말한 것을 다 알아들었다고 읽히지 않게 한다
```

이 둘만 지키면 어떤 문구든 괜찮습니다.

**이 경로로 오는 요청은 실측상 100%(합성 20/20)가 사용자가 말한 무언가를 못 알아들은
상태입니다.** 당연한 일입니다 — 향 표현을 알아들었다면 향으로 골랐을 테니까요.
그러니 *"더 말씀해 주세요"* 는 예외 문구가 아니라 **이 경우의 기본 문구**입니다.

⚠ **`unmatched` 를 화면에 그대로 띄우자는 뜻이 아닙니다.** 계약서가
*"`unmatched` 는 화면에 쓰지 않는다"* 로 이미 막아 뒀고, 그 판단은 그대로 둡니다.
못 알아들은 **내용**을 보여주지 않고, 못 알아들었다는 **사실**만 문구로 밝히면 됩니다.

### 3-4. 이유를 표시할 때

```
matchedData[].label   한국어라 그대로 쓸 수 있습니다
                      중성적인 · 여름에 어울리는 · 밤에 어울리는 · 미모사
matchedData[].value   내부 값입니다 — unisex · summer · night · mimosa
matched[].accord      내부 값입니다 — soapy · fresh  (기존 규칙 그대로)
```

`label` 을 그대로 쓸지 문장으로 다듬을지는 프론트 판단입니다. **다른 표기가 필요하면
말씀해 주세요** — 값 9개짜리 고정 표라 AI 쪽에서 바꾸기 쉽습니다.

### 3-5. [정해 주세요] 둘

```
① 위 ✅ 문구를 어떻게 다듬을지          말투와 길이는 프론트 판단입니다
② 이유를 목록 위에 한 줄로 둘지        2장 ①(최상위/결과별)과 같은 결정입니다
   향수 카드마다 붙일지                 백엔드와 함께 정해 주세요
```
