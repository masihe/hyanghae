## 0. 한 줄

**AI 서버는 떠 있지만 API 키가 없어서 자연어 추천이 절반만 돕니다. 각자 `.env` 에 키를 넣어야 합니다.**

키는 팀 저장소에 올릴 수 없습니다(`.gitignore` 대상). 그래서 **각자 한 번씩** 해야 합니다.

---

## 1. 키를 넣는 방법

팀 저장소 **루트**에 `.env` 파일을 만들고 한 줄 적습니다.

```
C:\Users\SSAFY\Desktop\S15P21E203\.env
```

```dotenv
GMS_API_KEY=담당자에게받은키
```

**따옴표를 붙이지 마십시오.** `GMS_API_KEY="abc"` 로 적으면 따옴표까지 값이 됩니다.

모델 이름은 적지 않아도 됩니다. 기본값이 이미 들어 있습니다 — AI 서버는 `gpt-5.4-nano`,
백엔드는 `gpt-5-nano` 입니다.

그다음 AI 컨테이너를 다시 만듭니다. **`.env` 는 컨테이너를 만들 때만 읽힙니다** —
돌고 있는 컨테이너에는 반영되지 않습니다.

```bash
cd C:/Users/SSAFY/Desktop/S15P21E203
docker compose -f compose.manual-test.yaml up -d ai
```

확인은 기동 로그로 합니다.

```bash
docker compose -f compose.manual-test.yaml logs ai --tail 20
```

```
키 없을 때   ①단계 LLM 구조화 꺼짐 — GMS_API_KEY 가 없다
키 있을 때   ①단계 LLM 구조화 켜짐 (model=gpt-5.4-nano prompt=4f0a368d98b41338)
```

### 자세한 안내는 이미 있습니다

`docs/local-development-guide.md` 9장입니다. 팀 저장소에 있어 누구나 열 수 있습니다.

### ⚠ `.env` 를 커밋하지 마십시오

`.gitignore` 7~9행이 막고 있습니다. `git status` 에 `.env` 가 안 보이는 것이 정상입니다.
보이면 알려주십시오. **한 번 푸시하면 git 이력에서 지우기가 사실상 불가능합니다.**

## 2. 키가 없어도 서버는 돕니다 — 다만 절반입니다 [측정]

AI 서버에 직접 요청해 본 결과입니다.

```
"빨래 냄새 나는 향수 찾고 있어"    OK · 5개    사전에 "빨래" 가 있다
"포근하고 달지 않은 향"           0개
"여성스러운 향 추천해줘"           0개
"데이트에 어울리는 섹시한 향"       0개
```

**API 계약은 정상으로 응답합니다.** `status` · `conditions` · `diagnostics` 가 다 옵니다.
그래서 **연동 작업은 지금 시작할 수 있습니다.** 다만 화면에 보여줄 결과가 대부분 비어
있어서 동작을 눈으로 확인하기 어렵습니다.

키를 넣으면 문장에서 조건을 뽑는 단계(①단계)가 켜집니다.

## 3. ⑤단계 미매칭 추정이 붙습니다 (MR S15P21E203-308)

사전이 조건을 **하나도** 못 뽑았을 때, 못 받은 표현을 LLM 에 한 번 더 물어 향 특성으로
바꿉니다. 실사용 설문 143건 기준으로 **조건 추출이 60.8% → 85.3%** 입니다 [측정].

### ⚠ 응답이 느려집니다 [측정]

```
추정이 안 도는 문장                1.3 ~ 1.6초   사전이 이미 조건을 잡은 경우
추정이 도는 문장 (처음 보는 표현)    3.1 ~ 4.6초
①단계가 같은 표현을 다시 뽑으면      1.4초대       캐시가 걸려 GMS 를 안 부릅니다
```

한 프로세스 안에서 같은 문장 3회 실측이 `3.29s / 1.53s / 1.37s` 였습니다.
재시작 직후 첫 호출은 `4.64s` 였습니다.

### ⚠ 캐시가 생각보다 자주 비껴갑니다

**캐시 키는 사용자 문장이 아니라 ①단계가 뽑은 표현입니다.** 그런데 ①단계는 같은
문장에서도 매번 조금 다른 표현을 뽑습니다. 로그에서 확인한 실제 예입니다 [측정].

```
원문 "포근하고 달지 않은 향" 에서 ①단계가 뽑은 표현들
    "포근하고 달지 않은 향"  (통째로)
    "포근한 향"    -> warm spicy · sweet · amber
    "포근한 느낌"   -> amber
    "달지 않은 향"  -> bitter
    "cozy"        -> warm spicy        영어로 뽑은 적도 있습니다
    "not sweet"   -> bitter
```

표현이 달라지면 키가 안 맞아 **캐시에 있어도 GMS 를 다시 부릅니다.** 재시작 뒤
"캐시 5개를 읽었다" 고 나오는데도 첫 호출이 4.64초였던 이유입니다.

**즉 "같은 문장을 두 번 넣으면 빠르다" 가 항상 성립하지 않습니다.** 별도 이슈로
다루기로 했습니다.

화면에서 로딩 표시를 3초 이상 버틸 수 있게 잡아 주십시오. 백엔드 타임아웃도 확인이
필요합니다 — 계약 문서는 8초 예산으로 적혀 있습니다.

### 끄는 법 — ⚠ 로컬에서는 한 줄이 더 필요합니다

코드에는 스위치가 있습니다. `off` · `0` · `false` 중 아무 값이나 됩니다.

```
NLR_ESTIMATOR=off        이 기능이 붙기 전과 똑같이 동작합니다
```

**그런데 `compose.manual-test.yaml` 의 `ai` 서비스에 이 변수가 없습니다** [측정].
컨테이너가 받는 것은 `GMS_API_KEY` · `GMS_MODEL` · `NLR_LOG_PATH` 셋뿐입니다.
**`.env` 에 적어도 전달되지 않습니다.**

로컬에서 끄려면 `ai` 서비스에 한 줄이 필요합니다.

```yaml
  ai:
    environment:
      NLR_ESTIMATOR: ${NLR_ESTIMATOR:-on}     # 이 줄이 없습니다
```

이 파일은 AI 담당 범위 밖(루트 설정)이라 손대지 않았습니다. **필요하면 인프라·공통
담당이 넣어 주십시오.** 배포 환경은 환경변수를 직접 넣으므로 스위치가 그대로 동작합니다.

### 키를 빼는 것은 대안이 아닙니다

`GMS_API_KEY` 가 없으면 추정기가 자동으로 꺼집니다. **다만 문장에서 표현을 뽑는
①단계 LLM 구조화도 같이 꺼집니다.** 둘이 같은 조건으로 묶여 있습니다
(`server.py` 119행 — `if ESTIMATOR_ENABLED and llm["enabled"]`).

즉 키를 빼면 2장의 "절반만 도는" 상태로 돌아갑니다. **추정기만 끄는 수단은 아닙니다.**

어느 상태인지는 기동 로그로 확인하십시오. 켜짐/꺼짐이 남습니다.

### ⚠ 같은 문장이 항상 같은 결과는 아닙니다

흔들리는 곳이 **두 군데**입니다.

```
①단계가 뽑는 표현      같은 문장에서 "포근한 향" · "포근한 느낌" · "cozy" 로 갈립니다
추정이 내는 accord     같은 표현에도 다른 답을 줍니다
```

캐시는 **뒤쪽만** 막습니다. 같은 표현을 다시 받으면 먼저 온 답을 그대로 씁니다.
앞쪽은 막지 못합니다 — 표현이 달라지면 캐시 키가 달라집니다.

실제로 `"포근하고 달지 않은 향"` 이 세 실행에서 이렇게 갈렸습니다 [측정].

```
amber · bitter · sweet · warm spicy
amber · bitter
bitter · warm spicy
```

**화면 테스트에서 어제와 오늘 결과가 다르면 이것일 수 있습니다.** 버그로 보이기 쉬운
지점이라 먼저 알려 둡니다.

### 알려진 한계 하나

부정 표현이 긍정 조건이 될 수 있습니다. 추정 결과가 `core`(원하는 향)에만 들어가고
`avoid`(피하고 싶은 향)로 가는 길이 없기 때문입니다.

설문 143건으로 재니 부정이 든 표현 5개 중 **4개는 해석이 맞았고 1개가 틀렸습니다**
(`"너무 쎈 향은 싫어함" → bitter`) [측정 · `nlr_engineering_notes.md` 21번].
**되돌릴 수 없는 문제는 아닙니다** — 위 스위치로 끌 수 있습니다. 다만 로컬에서는
compose 에 한 줄을 넣어야 그 스위치가 닿습니다(위 「끄는 법」).

## 4. 연동할 때 걸리는 것

### 요청 필드 이름이 홉마다 다릅니다

제가 여기서 한 번 막혔습니다. 계약 문서가 맞고 제가 잘못 읽었습니다.

```
프론트엔드 → 백엔드     { "query": "..." }     nlr_api_contract.md 70행
백엔드 → AI 서버        { "text": "..." }      nlr_api_contract.md 177행
```

AI 서버에 `query` 로 보내면 `400 NLR_INVALID_REQUEST` 가 옵니다.

### 향수 번호가 DB 번호와 다릅니다

AI 응답이 주는 것은 `fragranticaId`(Fragrantica 원본 번호)입니다. DB 의
`perfumes.perfume_id` 와 **다른 값**입니다. `perfumes.fragrantica_id` 로 찾아 바꿔야
합니다.

### 조건이 0개일 때 인기 향수를 대신 보여주면 안 됩니다

계약 문서 116행의 경고입니다. 추천처럼 보이지만 근거가 없어서 *"왜 이게 나왔냐"* 에
답할 수 없고 요구사항 NLR-07(추천 이유 제공)을 어깁니다. `status` 가 `NO_CONDITION` 이면
**다시 입력하도록 유도**해 주십시오.

### `ai/logs` 볼륨이 필요합니다

추정 캐시가 그 파일입니다. 볼륨이 없으면 재시작마다 캐시가 비고 답이 달라집니다.
`compose.manual-test.yaml` 에는 이미 붙어 있습니다(`nlr-logs`).

아래를 그대로 복사해 쓰시면 됩니다.

```

AI 서버는 떠 있는데 GMS 키가 없어서 문장에서 조건을 뽑는 단계가 꺼져 있습니다.
지금은 사전에 있는 표현("빨래" 등)만 잡혀서 대부분 결과가 0개로 나옵니다.

1. 팀 저장소 루트에 .env 파일을 만들고 한 줄 넣어 주세요 (따옴표 없이)
     GMS_API_KEY=담당자에게받은키
2. AI 컨테이너를 다시 만들어 주세요
     docker compose -f compose.manual-test.yaml up -d ai

자세한 건 docs/local-development-guide.md 9장에 있습니다.
.env 는 커밋되지 않습니다(.gitignore). 각자 한 번씩 해주셔야 합니다.
```

## 6. 확인하지 못한 것

- **배포된 환경은 확인하지 못했습니다.** 제가 본 것은 `compose.manual-test.yaml` 로 뜬
  로컬 컨테이너뿐입니다. 배포 서버의 AI 컨테이너에 키가 들어가 있는지는 인프라 담당이
  확인해야 합니다(`ai/docs/nlr_api_contract.md` 391행이 그 몫으로 적어 뒀습니다)
- **지연은 로컬 실측입니다.** 배포 환경의 네트워크에서는 다를 수 있습니다
- **백엔드·화면과 이어서 보지 않았습니다.** AI 서버에 직접 요청한 결과입니다
- **조건이 맞는지는 재지 못합니다.** 설문 143건에 정답 라벨이 없습니다
  (`spec.md` §8 3번). 조건을 뽑게 됐다는 것과 그 조건이 맞다는 것은 다릅니다
- **부정 표현 표본이 16개입니다.** 이 수로 비율을 말하면 한 건이 6%를 움직입니다
