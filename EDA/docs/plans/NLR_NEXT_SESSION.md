## 2. 막혀 있는 것 ① — 오타 환각. 결정 넷이 필요하다

**가장 나쁜 문제인데 가장 크다.** 사용자가 정상적으로 요청했는데 **근거까지 지어낸 엉뚱한
결과**가 나가는 유일한 경우다 (측정 기록 25번).

```
"빨레 냄새 나는 향수 찾아줘"   3회 모두 다른 향수
  leather·rubber / leather·tobacco·woody / gasoline·industrial glue·leather

⑤단계의 설명   "빨레(바퀴/롤러로 비유되는 고무·플라스틱 계열의 냄새)는 타이어·고무 같은
              공업성 느낌과 함께 휘발성 가솔린 계열의 특성이..."
```

`ㅁㄴㅇㄹ` 에는 빈 목록을 내면서 `빨레` 에는 이러는 이유는 — **의미 없는 글자는 의미
없다고 판단하지만, 그럴듯한 한국어 오타는 "모르는 단어" 로 보고 해석하려 들기 때문**이다.

### 설계 방향 (GPT 조사가 권한 것 · 우리 구조에 맞음)

⑤단계 **앞에** 검문소를 세운다. LLM 을 결정권자가 아니라 후보 제안자로 강등시킨다.

```
사전이 조건을 하나도 못 뽑음
   ↓
이 표현이 사전에 있는 말의 오타인가?  (사전 표면형 170개와 편집거리 비교)
   ↓
거리 1이고 후보가 하나뿐   ->  교정해서 사전 경로로
거리 1인데 후보가 여럿     ->  화면에 "혹시 '빨래' 를 찾으셨나요?"
가까운 말이 없음          ->  ⑤단계로 보내지 않고 빈 결과
   ↓
창의적 표현("도서관 냄새")만 ⑤단계 LLM 으로
```

### 정해야 할 넷 — **작성자가 임의로 정하면 안 된다**

```
1. 편집거리 몇까지 자동 교정하는가         1 ? 2 ?
2. 2글자 단어에도 같은 기준을 쓰는가       `숲` 과 `숯` 은 거리 1인데 뜻이 다르다
3. 후보가 여럿이면 어떻게 하는가           화면에 물어볼 것인가, 그냥 포기할 것인가
4. 교정한 사실을 사용자에게 보여주는가      "'빨레' 를 '빨래' 로 이해했어요"
```

**4번은 프론트엔드 담당과도 얘기해야 한다.** 화면 문구가 걸린다.

**잃는 것도 미리 적어 둔다** — 보수적으로 잡으면 고칠 수 있는 오타도 빈 결과가 된다.
조사 보고서 표현으로는 *"잘못된 5개 향수보다 무응답을 더 싸게 보는 정책 선택"* 이다.

### 재료는 있다

`nlr_engine` 의 `index["lexicon_surface"]` 가 표면형 170개를 갖고 있다. 편집거리는
순수 파이썬으로 충분하다 — **새 의존성이 필요 없다**(조사도 같은 판단).
