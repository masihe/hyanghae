## 2. 오늘 측정해서 결론 난 것 — 다시 하지 말 것

`DECISIONS.md` **N11** 에 기록했다. 요약하면 이렇다.

> **표현을 accord 가중 조합으로 바꾸는 방향을 세 번 재봤고 모두 개선이 없었다.**

```
44  사전 구조 변경(IDENTITY 재라벨 · 음차 이전)      효과 0. 엔진이 그 컬럼을 안 읽는다
46  accord 확장 + AND 제거 + IDF 가중              명확히 나쁨. 상위 5 겹침 0~2/5
47  core AND 유지 + 가점(H1·H2)                    H1 효과 없음 · H2 −0.0018
```

**왜 안 됐는지가 중요하다.**

- **하드 AND 는 좁혀서 나쁜 게 아니라 좁혀서 맞았다.** `빨래` 를 2→7 accord 로 늘려
  AND 를 걸면 후보가 518 → **0** 이 된다. AND 를 버리면 조연 accord 가 주연을 이긴다
  (`빨래` 1위가 `soapy` 없는 향수가 됨)
- **가중치로 쓸 숫자가 없다.** 배수(lift)는 27칸 중 10칸만 쓸 수 있고(순환 4 · 반증 2 ·
  미측정 11), `ai_summary` 는 평가자 중앙 628명인 향수에만 붙어 롱테일 보증이 안 된다.
  IDF 는 구멍이 없지만 **의미를 모른다**(`이불` 의 주인공을 `soapy` 로 만든다)
- **NDCG 가 이 변화를 평가하지 못한다.** 정답 키에 가점 accord 가 없다

**다시 열 조건** — 회피 품질을 사람이 판정한 평가셋이 생기거나, 표현별 기여도를 직접
측정하거나, 미매칭 로그가 쌓여 실사용 분포를 알게 됐을 때.

## 3. 아직 결정 안 난 것 — 사람이 정해야 한다

### 회피가 59개 중 8개만 동작한다

```
avoid 항목 59개 (고유 46개)
   8개  accord 에 닿음          sweet · leather · citrus
   6개  매칭만 고치면 닿음        too sweet · cloying floral · rough leather
  45개  사전에도 accord 에도 없음  too heavy · 유치한 · 끈적 · 평범한 꽃향
```

**45개 중 상당수는 매핑하면 안 되는 말이다** — `cute` · `feminine` · `classic` ·
`유치한` 은 향이 아니다. 레퍼런스 조사도 *"억지로 accord 로 매핑하지 않는다"* 를 권했다.

정해야 할 것 넷 (레퍼런스 조사 `자연어 향수 추천의 회피 로직 설계` 가 답을 제시했다)

| | 질문 | 조사의 권고 |
|---|---|---|
| Q1 | 회피도 사전을 태울 것인가 | 예. 단 relation 으로 hard/soft/no-map 을 나눈다 |
| Q2 | 표현의 accord 를 전부 뺄 것인가 | **아니오.** component 삭제 대신 concept 억제 |
| Q3 | 부분 일치를 허용할 것인가 | substring 금지. 경계 인식 + 최장 구문 우선 |
| Q4 | 향이 아닌 표현은 | 매핑하지 않고 로그 + 화면 고지 |

**Q3 은 실험했다(45번).** 경계 매칭으로 4 → 10개가 되지만 `sweet orange` 같은
과잉 제거가 6개 중 1~2개 생기고, NDCG 가 0.4688 → 0.4668 로 내려간다.
**순이익 4~5개.** 판단할 지표가 없어 보류했다.

### 화면 고지를 어떻게 할 것인가

논의 결과 **"실패했다고 말하지 않는다"** 로 정리됐다. 대신 **적용한 조건을 보여준다.**
계약서의 `reasons[].phrase` 가 이미 *"당신이 쓴 말 → 이렇게 이해했습니다"* 구조라
회피도 같은 자리에 넣으면 된다. 못 한 것은 칩에 안 나타나므로 사용자가 스스로 안다.

예외는 **결과가 0개일 때** 다. 그때는 사용자가 다음 행동을 해야 하므로 알린다
(계약서가 `NO_CONDITION` 을 그렇게 정했다).

### 별도로 다룰 발견 셋

1. **`ozonic` 이 네 표현에 공통 신호** — 빨래 · 깨끗한 · 촉촉한 · 비 오는 숲.
   사전에 한 번도 들어 있지 않다
2. **`머스크 → soapy` · `이불 → soapy` 가 반증인데 `core` 다.** 같은 판정을 받은
   `호텔` · `차가운` 은 `optional`+`NO_MAPPING` 으로 강등됐다. **왜 둘만 남았는지 모른다**

- 팀 저장소는 **`ai/` 밖을 절대 건드리지 않는다.** `backend/` · `frontend/` · `Jenkinsfile` 은 다른 담당

- API 키를 코드·문서·커밋 어디에도 적지 않는다
- **평가 데이터(golden set xlsx)와 설문 155건은 건드리지 않는다.** 설문은 채점용이라
  사전 확장이나 규칙 선택에 쓰면 안 된다(`AGENTS.md` — holdout 은 tuning 에 못 쓴다)
- `domain_lexicon_v1.csv` · `v1_1.csv` 는 보존본이라 덮어쓰지 않는다
- `EDA/` 의 노트북은 실행하지 않는다
- **측정하지 않은 개선을 개선이라고 말하지 않는다**
