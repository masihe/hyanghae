# 향 지도 핵심 결정 6개 — Y-Statement

이 문서는 **발표·인계용 발췌본**이다. 원본은 `docs/DECISIONS.md`(D1~D31)이고 이 파일은 그중 6개를
`.claude/commands/decision.md` 의 Y-Statement 형식으로 옮긴 것이다. **원본은 한 줄도 바꾸지 않았다.**

고른 기준은 셋이다 — 발표 Q&A 에서 "왜 이렇게 했나요" 가 나올 만한 것, 기각한 대안이 있는 것,
되돌리기 어려운 것.

**이관은 형식 변환이다.** 결론·근거·기각 이유는 원문 문장을 그대로 인용했고, 새로 쓴 것은 슬롯을 잇는
접속부(`~에서`, `~에 직면하여`, `~을 받아들인다`)뿐이다. 원문에 없는 수치는 만들지 않았다.

여섯 슬롯 문장에는 **주 결정 하나 + 주 기각 하나**만 넣었다. 나머지 결정·기각·Trade-off 는
`- 근거:` 줄에 `함께 ~ —` 로 붙였다.

`⟨미정 — X⟩` 는 **원문에 없어서 채우지 못한 칸**이다. 추측해서 채우지 않았다. 목록은 맨 아래에 있다.

### D1: 향수 간 유사도를 어떻게 정의할 것인가

- 날짜: 2026-09-04 (기록 시점 — 커밋 `5a9b0c8`)
- 상태: ⟨미정 — B-1⟩

EDA 04~09가 이미 `reminds_me_of`를 정답으로 삼아 향수-향수 유사도를 측정 완료한 상황에서,
향 지도는 "가까이 배치할 데이터적 이유"가 필요한데 유사도를 새로 설계해야 하는가에 직면하여,
기존 EDA 04~06의 Base Similarity 재사용(`sim = 0.5·cosine(accord strength, L2) + 0.5·IDF 가중 Jaccard(note 합집합)`)을 택하고
`reminds_me_of` 그래프 자체를 거리로 사용하는 것을 택하지 않았다.
⟨미정 — C-1⟩을 위해서이며,
accord는 향수당 8개 상한이 있어 표현력에 천장이 있고, note는 표층 문자열 기반이라 의미적 유사성(예: 서로 다른 이름의 같은 원료)을 못 잡는 것을 받아들인다.

- 근거: `verify_similarity.py`로 EDA 04의 Development 700 평가를 재현했다. **소수점 4자리까지 일치**했다 — Accord Cosine recall@10 0.1868 / ndcg@10 0.1688, Note Jaccard 0.2545 / 0.2345, Accord + Note 0.2900 / 0.2668, 채택한 **Accord + IDF Note 0.3010 / 0.2709**. query 수(12,150 / 3,835), vocab(92 / 2,523), nnz(1,000,570 / 1,091,811) 전부 일치.
  - 주 기각 이유 — (3)은 정답을 입력으로 쓰는 것이라 평가가 불가능해진다. 게다가 top1000 중 신뢰 간선 보유 노드가 451개뿐이라 나머지는 배치할 수 없다.
  - 함께 기각한 것 — description 텍스트 임베딩. (2)는 description 품질이 미검증이고 별도 검증 절차가 필요해 2주 안에 무리다.
  - 재사용의 근거 — EDA 04~09가 이미 `reminds_me_of`를 정답으로 삼아 향수-향수 유사도를 측정 완료했다. 향 지도가 새로 푸는 문제는 유사도가 아니라 **2D 투영**이다.
- 관련: `verify_similarity.py`, EDA 04~06, `docs/DECISIONS.md` D1

### D2: 2D 배치 방법 — MDS에서 UMAP으로 뒤집음

- 날짜: 2026-09-04 (기록 시점 — 커밋 `5a9b0c8`)
- 상태: ⟨미정 — B-2⟩

최초 판단은 MDS였고 의존성 논거가 약하다는 지적을 받고 실제 거리행렬을 측정한 상황에서,
1000×1000 거리행렬을 2D로 어떻게 떨어뜨릴 것인가에 직면하여,
UMAP(`metric='precomputed'`, `n_neighbors=10`, `min_dist=0.1`, `random_state=42`)을 택하고
Metric MDS를 택하지 않았다.
⟨미정 — C-2⟩을 위해서이며,
"지도상 거리 = 유사도"라고 말할 수 없게 되는 것을 받아들인다.

- 근거: 출처 `results/layout_comparison.csv`. trust@10 / kNN overlap@10 / reminds_pct 순으로 random 0.4980 / 0.0086 / 0.5058, pca 0.7523 / 0.0810 / 0.2019, mds 0.7674 / 0.0835 / 0.2452, **umap nn=10 md=0.1 (채택) 0.9387 / 0.3888 / 0.1766**. `n_neighbors` 3개 값에서 지표가 일관됐다(trust@10 0.90~0.94). 단일 설정의 우연이 아니다.
  - 주 기각 이유 — 국소 신호 구간(1~20위)에 드는 pair 비율이 2.77%인데 그 pair 가 차지하는 제곱거리 합은 1.24%다. MDS는 최적화 노력의 **98.8%를 정보 없는 pair**에 쓴다. 고차원 희소 데이터의 거리 집중 현상이다. 예측이 맞았다 — MDS는 kNN overlap 0.0835로 PCA(0.0810)를 겨우 넘고, `reminds_pct`는 오히려 PCA보다 **나쁘다**(0.2452 vs 0.2019). UMAP은 kNN overlap에서 MDS의 **4.7배**.
  - 함께 기각한 것 — t-SNE, PCA.
  - 추가 근거 — CLAUDE.md가 "계열 내부 관계 우선, 전 계열 통합 좌표계는 필수 아님"이라고 명시한다. 전역 좌표 일관성이 MDS의 유일한 강점인데 그게 요구사항이 아니었다.
  - 감수한 것의 보완 — UMAP 좌표는 거리 척도가 아니다. 대신 정확한 답은 고차원 기준 `neighbors` 배열이 담당하도록 설계했고, JSON에 `distance_is_metric: false`를 명시했다. 다만 위 측정대로 MDS로도 이 데이터에선 낮은 stress를 얻을 수 없으므로 실질 손실은 없다.
  - 갱신 전 값은 원본 `DECISIONS.md` D2 "갱신 전 값 (보존)" 표에 남아 있다.
- 관련: `results/layout_comparison.csv`, `docs/DECISIONS.md` D2

### D3: 지도에 올릴 향수 선정

- 날짜: 2026-09-04 (기록 시점 — 커밋 `5a9b0c8`)
- 상태: ⟨미정 — B-3⟩

기획 초안이 "대표 향수 약 200개"였던 상황에서,
어떤 향수를 지도에 올릴 것인가 — 인기 top200은 신뢰 간선 보유 노드가 70 / 200뿐이라 200개로는 검증이 불가능하다는 문제에 직면하여,
화면 200개 + 좌표 1000개, 계열(dominant accord)별 **제곱근 비례 할당**(하한 5 / 상한 60), 후보 풀 `people >= 500`을 택하고
인기순 top1000을 택하지 않았다.
계열 커버리지 +38%와 브랜드 다양성을 위해서이며,
**신뢰 간선 4.7% 손실**과, 최소 투표수가 3,309 → 501로 내려가 "사용자가 아는 향수" 전제가 약간 약해지는 것을 받아들인다.

- 근거: 출처 `results/selection_comparison.csv`. 인기순 top1000(A) → 그룹→accord 할당(B) 로 dominant accord 커버리지 42종 → **58종(+38.1%)**, 브랜드 수 182 → **223(+22.5%)**, 상위 10개 브랜드 점유율 29.6% → **25.3%(−4.3%p)**, 신뢰 간선 915 → **872(−4.7%)**. 두 행 모두 같은 후보 풀(`usable_pool`, group 결측 제외)에서 뽑은 값이라 A와 B가 같은 조건에서 비교된다. 절대량(신뢰 간선 872개)이 검증에 충분하다.
  - 200개로는 검증이 불가능한 근거 — 집합별 신뢰 간선 보유 노드: 인기 top200 **70 / 200**, top1000 483 / 1000, top2000 1,145 / 2000.
  - 함께 기각한 것 — 후보 풀을 `people>=200`까지 넓히면 계열이 66종으로 늘지만 신뢰 간선이 883으로 더 줄고 최소 투표수가 203까지 떨어져 채택하지 않았다.
  - 갱신 전 값은 원본 `DECISIONS.md` D3 "갱신 전 값 (보존)" 줄에 남아 있다.
- 관련: `results/selection_comparison.csv`, `docs/DECISIONS.md` D3

### D22: 영역 표현 방식과 향 계열 체계 확정 — C8b · Set B 9계열

- 날짜: 2026-09-09 (기록 시점 — 커밋 `3166257`)
- 상태: ⟨미정 — B-5⟩

D9 가 클러스터 라벨을 UMAP target 으로 넣어 좌표 단계에서 섬을 가르려다 기각됐고 "k=12 는 유사도에서 나온 라벨이라 왜곡이 컸다. 향 계열 라벨로 하면 다를 것" 이라는 반론이 남아 있었으며 Phase 0 의 9계열도 `status: PROVISIONAL` 이었던 상황에서,
사용자가 향 지도를 탐색할 때 "여기가 어느 향 계열 구역인가"를 읽을 수 없다는 문제에 직면하여,
**C8b(계열 + 인식 축 혼합)를 메인 Territory 후보로** 택하고
C2 계열 supervised UMAP 을 택하지 않았다.
향해는 단순 유사 향수 검색이 아니라 향 계열을 탐색하는 지도이므로, 사람 유사성만 극대화하는 C8a 보다 영역 가독성과 사람 판단을 동시에 개선한 C8b 가 서비스 목적에 맞기 때문이며,
**C8b 가 kNN overlap@10 을 0.3888 → 0.3146 으로 잃는 것**을 받아들인다.

- 근거: 합격 기준은 실행 전에 확정했고 결과를 보고 바꾸지 않았다 — Gate A(계열 횡단 신뢰 쌍의 2D 근접도) ≤ **0.3115**, Gate B(trustworthiness@10) ≥ **0.90**, Global 1,000 · 412쌍. C8b 는 Gate A Δ **−0.0342**, trust@10 0.9191, Korea ratio **3.913** / Global ratio **5.061**, 영역 조각 24 → **15**, 정답 간선 근접도 0.1760 → **0.1470**.

  - 함께 기각한 것 — C4 해역 고정(+0.2777) · C6 앵커 + 국소(+0.3140) · C5 휠 앵커 RadViz(Gate A 는 통과했으나 trust@10 **0.7068** · overlap@10 **0.0705** 로 Gate B 탈락) · 계열 정의 Set A(휠 4대 그룹, ratio 1.486 에 Korea 200 에서 16개 결측) · Set C(자동 군집, ratio 4.162 로 Set B 와 사실상 동률이지만 **점수가 순환이다** — 좌표를 만든 것과 같은 거리행렬에서 나온 군집이다).
  - 함께 정한 것 — C1 은 baseline·복구용으로 보존 / **Set B 9계열을 이후 Phase 의 기준 계열 체계로 확정** / C3 semi w=0.35 하나만 안전 대안으로 유지.
  - 충돌의 크기 — Global 1,000 안의 신뢰 간선 872쌍 중 **412쌍(47.2%)이 계열을 넘는다.** 계열별로 뭉치게 만들면 그 412쌍이 갈라진다.
  - 함께 감수한 것 — C8b 는 아직 한 점(계열 0.35 · 인식 0.15)에서만 쟀다 / 인식 축은 사용자 투표에 의존한다 / Set B 의 미해결 쟁점 2개(`powdery` 보유율 47.7%, Fruity 가 Korea 200 에서 8개뿐인 것)를 Phase 4 로 넘겼다.
