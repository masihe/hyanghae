향 지도 데이터 — DB 담당자용

국내 대표 향수 200개의 향 지도. 어떤 데이터를 어떤 표에 넣으면 되는지.

측정 은 실제 데이터에서 확인한 값입니다. 여기에 맞지 않게 만들면 데이터가 들어가지 않으니 그대로 지켜 주세요.

제안 은 저희 판단일 뿐입니다. 참고만 하시고 실제 설계는 담당자분이 정하시면 됩니다. 그대로 구현하지 않으셔도 괜찮습니다.

이 문서를 다 읽지 않아도 되는 요약

  1. 먼저 하나 정해 주세요 — perfumes 테이블에서 향수를 식별할 방법이 필요합니다. 이게 정해지지 않으면 나머지가 전부 막힙니다 (아래 1번).
  2. 표 5개를 만듭니다. 4개는 지금 ERD 에 있는 것과 거의 같고, 1개는 새로 필요합니다 (아래 2번).
  3. CSV 6개를 순서대로 넣습니다. seed/ 폴더에 있습니다.

넘겨드리는 것은 국내 대표 향수 200개를 향 지도 위에 배치한 결과입니다. 향수마다 지도 위 위치가 있고, 어떤 향 계열에 속하는지, 어떤 향수와 닮았는지가 붙어 있습니다. 향 계열은 시트러스 · 플로럴 · 우디 같은 9개입니다.

1먼저 정해야 하는 것 — 향수를 무엇으로 식별할까요

저희 데이터는 향수를 Fragrantica 의 id 로 식별합니다. 향수 데이터의 원천이 Fragrantica 라서 그렇습니다. 그런데 지금 ERD 의 perfumes 테이블에는 외부 id 를 담는 컬럼이 없습니다.

그래서 넘겨드리는 CSV 를 perfumes 행과 이어붙일 방법이 없습니다. 브랜드명과 향수명으로 맞추는 방법도 있지만, 같은 향수가 농도나 표기만 달라도 여러 줄로 존재해서 정확하지 않습니다.

제안 perfumes 에 fragrantica_id BIGINT UNIQUE 컬럼을 추가하는 것이 가장 단순합니다.

컬럼 추가가 부담스러우면 매핑 테이블을 따로 두는 방법도 있습니다. 어느 쪽이든 정해 주시면 저희가 CSV 를 그 키로 다시 내보내 드립니다. 지금 CSV 는 전부 fragrantica_id 로 되어 있습니다.

2지금 설계로는 담기지 않는 것 — 향수 하나가 계열 여러 개

향수는 보통 한 가지 향만 나지 않습니다. 예를 들어 Byredo 의 Blanche 는 플로럴 0.60 + 머스크·파우더리 0.32 로, 두 계열에 걸쳐 있습니다. 이런 향수가 지도에서 두 영역 사이에 놓여서, 사용자가 한 계열에서 다른 계열로 넘어가는 다리가 됩니다.

측정 향수 200개 중 계열이 1개인 향수가 105개, 2개가 87개, 3개가 8개입니다. 향수당 평균 1.515개이고 3개를 넘는 향수는 없습니다. 전부 합치면 303행이 됩니다.

그런데 지금 perfume_map_points 의 scent_region_id BIGINT NOT NULL 은 영역을 하나만 담을 수 있습니다. 이대로면 두 번째·세 번째 계열이 버려지고, 지도에서 경계에 놓이는 향수를 표현할 수 없습니다.

제안 향수 ↔ 계열 표를 따로 두는 것을 제안합니다 (perfume_id · family_key · weight · rank).

perfume_map_points.scent_region_id 는 가중치가 가장 큰 계열을 넣어 그대로 두셔도 되고, 빼셔도 됩니다. CSV 에 primary_family_key 로 함께 넣어 두었습니다.

3그 밖에 안 맞는 곳 4가지

충돌이라기보다 "저희 데이터가 이 모양이라 이 컬럼으로는 안 들어갑니다" 정도의 이야기입니다.

① 향 계열 영역이 사각형이 아닙니다

측정 scent_regions 는 min_x · min_y · max_x · max_y 로 사각형만 담습니다. 그런데 향 계열 영역은 지도 위에 불규칙한 모양으로 퍼져 있고, 계열마다 조각이 1~5개입니다. 사각형으로는 모양을 그릴 수 없습니다.

제안 polygon JSONB 와 라벨 위치(anchor_x · anchor_y) 컬럼을 더하는 것을 제안합니다.

② scent_regions 가 지금 무엇을 담고 있는지 저희가 모릅니다

user_preference_regions 가 이 테이블을 참조하고 있어서, 기존 행이 있다면 의미가 바뀌는 문제가 생깁니다. 확인 부탁드립니다.

참고로 이전 버전 지도에는 데이터로 자동 묶은 영역 7개가 있었는데, 그 7개는 한글 이름을 붙일 수 없어서 이번에 버렸습니다. 향 계열 9개만 넘겨드립니다.

③ 닮은 향수 목록에 순서 컬럼이 필요합니다

측정 perfume_neighbors 는 (perfume_id, neighbor_perfume_id) 만 담습니다. 그런데 저희가 주는 목록은 닮은 순서대로 정렬된 상위 10개이고 유사도 값도 있습니다. 순서를 잃으면 "가장 닮은 향수" 를 알 수 없게 됩니다.

제안 rank INTEGER 와 similarity NUMERIC 을 더해 주세요.

④ 지도 배경은 DB 에 안 넣는 편이 낫습니다

지도에는 땅과 바다, 색면, 해안선이 있습니다. 이건 향수별 데이터가 아니라 지도를 128×108 칸으로 나눈 격자라서, 조회할 조건이 없고 지도를 다시 만들 때만 바뀝니다.

제안 이 부분은 scent_map_terrain.json 파일로 따로 드리니 정적 파일로 프론트에 바로 내려주는 것을 제안합니다. 팀에서 이미 그렇게 정했습니다.

4적재할 때 걸리기 쉬운 것 3가지

실제로 넣어 보면 막힐 수 있는 곳입니다. 미리 봐 두시면 좋습니다.

① 계열 가중치에 >= 0.24 제약을 걸면 적재가 실패합니다.

계열을 뽑는 기준은 0.24 지만, 가장 큰 계열은 기준에 못 미쳐도 반드시 넣습니다 (그러지 않으면 어느 계열에도 속하지 않는 향수가 생깁니다). 그래서 측정 실제 최솟값은 0.2 입니다.

쓰셔야 하는 제약은 weight > 0 AND weight <= 1 입니다.

② 향수별 가중치 합이 1.0 이 아닙니다.

측정 향수별 합이 0.20 ~ 1.00 사이입니다. 기준 미달인 작은 계열은 목록에서 빠지는데 남은 것을 다시 정규화하지 않았기 때문입니다.

그래서 SUM(weight) = 1 같은 제약을 걸면 안 되고, 1 - SUM(weight) 를 "기타 계열" 로 읽어서도 안 됩니다.

③ 좌표 CHECK (0~1) 은 향수 좌표에만 걸어야 합니다.

측정 향수 좌표는 x 0~1, y 0~0.83056 입니다. 그런데 계열 영역의 폴리곤과 라벨 위치는 좌표계가 다릅니다 — 지도 바깥으로 여백이 붙어 있어서 -0.04565 같은 음수가 나옵니다.

폴리곤 컬럼에 0~1 제약을 걸면 계열 9개가 전부 적재에 실패합니다.

5넘겨드리는 CSV 6개

seed/ accords.csv 60행 향 특성 이름 목록 scent_families.csv 9행 향 계열 9개 (이름 · 영역 · 라벨 위치) perfume_map_points.csv 200행 향수 좌표 perfume_map_families.csv 303행 향수 ↔ 계열 ← 새로 필요한 표 perfume_map_neighbors.csv 2000행 닮은 향수 (향수당 10개) perfume_map_accords.csv 1598행 향수의 향 특성 (향수당 7~8개)

모두 UTF-8(BOM) CSV 이라 Excel 로 바로 열립니다. 향수는 전부 fragrantica_id 로 되어 있으니, perfumes 와 조인해 perfume_id 로 바꿔 넣으시면 됩니다.

6적재 순서와 갱신

참조 관계 때문에 순서가 있습니다.

  1. accords.csv — 기존 accords 테이블이 이미 있으면 확인만
  2. scent_families.csv — 9행
  3. perfumes 에 향수 식별 컬럼 채우기 (1번 항목)
  4. perfume_map_points.csv — 200행
  5. perfume_map_families.csv — 303행
  6. perfume_map_neighbors.csv — 2000행
  7. perfume_map_accords.csv — 1598행

제안 갱신은 행 단위로 고치기보다 4~7번을 비우고 다시 넣는 쪽이 안전합니다. 지도를 다시 만들면 향수 200개의 좌표와 계열 영역이 전부 바뀌기 때문입니다 (일부만 바뀌는 일이 없습니다).

CREATE / ALTER 문 초안은 scent_map_proposal.sql 에 있습니다. 실행해 본 적이 없는 제안이니 팀 규약(네이밍 · is_active · 삭제 정책)에 맞게 검토해 주세요. 타입과 길이가 실제 값을 받는지는 저희가 확인했습니다.

확인이 필요한 것

  • 향수를 무엇으로 식별할까요. 정해 주시면 CSV 를 그 키로 다시 냅니다.
  • scent_regions 에 지금 행이 들어 있나요. 있으면 향 계열 9개를 같은 테이블에 넣을지, 새 테이블로 나눌지 정해야 합니다.
  • 향수별 계절·시간대 투표를 쓸까요. 데이터는 있는데(향수 200개 중 185개 · 181개) ERD 에 담을 곳이 없습니다. 지금 지도에는 필요하지 않아 이번 CSV 에서 뺐습니다. 쓰실 거면 표를 하나 더 만들어야 합니다.
