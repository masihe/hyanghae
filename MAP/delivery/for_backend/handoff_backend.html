향 지도 데이터 — 백엔드 담당자용

무엇을 조회해 프론트에 어떤 모양으로 내보내면 되는지.

측정 은 실제 데이터에서 확인한 값입니다. 여기에 맞지 않게 만들면 데이터가 들어가지 않으니 그대로 지켜 주세요.

제안 은 저희 판단일 뿐입니다. 참고만 하시고 실제 설계는 담당자분이 정하시면 됩니다. 그대로 구현하지 않으셔도 괜찮습니다.

이 문서를 다 읽지 않아도 되는 요약

  1. 지도를 처음 열 때 향수 200개와 향 계열 9개를 한 번에 내려주면 됩니다. 약 289 KB 이고 gzip 이면 47 KB 입니다.
  2. 지도 배경(땅 · 바다 · 색면 · 해안선)은 DB 를 거치지 않습니다. 정적 파일 하나로 프론트에 바로 내려주는 것을 제안합니다.
  3. "닮은 향수" 는 미리 계산돼 있습니다. 좌표로 거리를 계산하지 말고 저장된 목록을 그대로 내려주세요.

향 지도는 국내 대표 향수 200개를 향이 비슷한 것끼리 가까이 놓은 평면 지도입니다. 향수마다 좌표가 있고, 지도는 시트러스 · 플로럴 · 우디 같은 향 계열 9개 구역으로 나뉩니다. 사용자는 돛단배를 움직여 지도를 돌아다니면서 새 향수를 발견합니다.

1기능별로 무엇을 조회해 무엇을 돌려주나

제안 아래는 기능 명세의 향 지도 항목을 데이터에 대응시켜 본 것입니다. 엔드포인트를 어떻게 나눌지는 담당자분이 정하시면 됩니다.

지도를 처음 열 때 MAP-01 향 지도 조회

향수 200개의 좌표·이름·소속 계열과, 향 계열 9개의 이름·영역·라벨 위치를 한 번에 내려줍니다. 200개가 전부이므로 페이지 나눌 필요가 없습니다.

지도 배경은 이 응답에 넣지 않고, 정적 파일 주소만 알려주면 됩니다 (아래 3번).

향수를 눌렀을 때 MAP-05 지도 내 향수 선택 · MAP-07 향수 상세 이동

그 향수의 향 특성(향수당 7~8개, 세기 0~100)과 소속 계열, 그리고 닮은 향수 10개를 내려줍니다. 상세 페이지로 넘어가면 기존 향수 상세 API 를 쓰시면 됩니다.

닮은 향수를 보여줄 때 MAP-06 유사 향수 탐색

저장된 목록을 rank 순서로 그대로 내려주면 됩니다. 향수당 10개 고정이고 이미 닮은 순서로 정렬돼 있습니다.

이 유사도는 향 성분으로 계산한 값입니다. 지도 위 거리와 다릅니다 — 자세한 이유는 아래 4번에 있습니다.

추천 주변을 탐색할 때 MAP-11 추천 주변 향 탐색

추천된 향수를 중심으로 주변 향수를 보여주는 기능입니다. 여기서는 지도 좌표를 쓰는 게 맞습니다 — "화면에서 이 근처에 뭐가 있나" 를 묻는 것이기 때문입니다.

좌표는 0~1 범위라 사각형 범위 조회로 충분합니다. WHERE map_x BETWEEN ? AND ? AND map_y BETWEEN ? AND ?

다음에 갈 곳을 추천할 때 MAP-12~15 탐색 방향 추천

사용자를 어디로 보낼지는 취향 데이터로 정하는 별개의 문제입니다. 다만 목표 지점을 좌표로 표현할 수 있다는 점만 알려드립니다 — 특정 향수의 좌표를 쓰거나, 향 계열의 라벨 위치(anchor)를 그 계열의 대표 지점으로 쓸 수 있습니다.

돛단배 위치는 이미 map_exploration_states 에 좌표로 저장되게 되어 있으니 그대로 맞습니다.

3지도 배경은 왜 DB 를 거치지 않나

지도의 땅·바다와 계열 색면은 지도를 128×108 칸으로 나눈 격자입니다. 칸마다 숫자 하나가 들어 있어서 총 13,824칸 × 2장입니다. 해안선은 좌표 점 목록입니다.

이건 향수별 데이터가 아니라 지도 한 장에 딱 하나 있는 그림입니다. 조회할 조건이 없고, 지도를 다시 만들 때만 바뀌고, 사용자마다 다르지도 않습니다. DB 에 넣으면 제안 BE 가 매 요청마다 쓸 데없이 99 KB 를 지나 보내게 됩니다.

제안 그래서 scent_map_terrain.json 을 정적 파일로 두고 프론트가 한 번 받아 캐시하게 하는 것을 제안합니다. 버전은 파일명이나 쿼리스트링으로 관리하면 됩니다. 팀에서 이미 이 방향으로 정했습니다.

측정 gzip 을 켜면 둘 다 충분히 작습니다. 저희가 드리는 파일은 사람이 읽기 쉽게 들여쓰기가 되어 있어서, 그것만 지워도 절반이 됩니다.

4주의할 것 3가지

① "닮은 향수" 를 좌표로 계산하지 마세요.

지도 좌표는 향수 200개를 평면에 눌러 담은 결과입니다. 원래 향의 차이는 훨씬 많은 축으로 되어 있는데 그걸 2차원으로 줄인 것이라, 가까운 관계는 잘 보존되지만 거리 자체는 향의 차이와 정확히 대응하지 않습니다.

그래서 닮은 향수는 미리 계산해 저장해 두었습니다. 그 목록을 쓰시면 됩니다. 데이터에도 layout.distance_is_metric: false 로 표시해 두었습니다.

참고로 지도를 새로 만들면서 좌표는 200개 전부 바뀌었지만, 닮은 향수 목록은 이전 버전과 완전히 같습니다. 좌표와 무관하게 계산되기 때문입니다.

② 계열 비중의 합을 1.0 으로 가정하지 마세요.

측정 향수별 합이 0.20~1.00 사이입니다. 비중이 작은 계열은 목록에서 빠지는데 남은 것을 다시 정규화하지 않았습니다. 1 - 합 은 "기타 계열" 이라는 뜻이 아닙니다.

③ 좌표계가 두 개입니다.

측정 향수 좌표는 0~1 인데, 계열 영역의 폴리곤과 라벨 위치는 다른 좌표계입니다 (지도 바깥으로 여백이 붙어서 -0.04565 같은 음수가 나옵니다). 그대로 내려주시고 변환은 하지 마세요 — 프론트가 각각 맞게 처리합니다.

확인이 필요한 것

  • 지도 배경을 정적 파일로 낼 수 있나요. 어려우면 DB 에 넣는 방법도 있어서, 그쪽이면 알려주세요.
  • 매칭 근거를 API 로 내보낼 일이 있나요. 향수마다 "왜 이 향수와 매칭했는지" 설명 문자열이 있는데 측정 73종의 자유 형식 문장이라 필터링에는 못 씁니다. 필요하면 정리해서 다시 드립니다.
  • 지도 데이터 버전을 어떻게 알릴까요. 지금은 만든 시각을 넣어 두었습니다.
