향 지도 데이터 — 프론트 담당자용

받은 데이터로 지도를 화면에 그리는 방법. 문서 안에서 실제로 그려 봅니다.

측정 은 실제 데이터에서 확인한 값입니다. 여기에 맞지 않게 만들면 데이터가 들어가지 않으니 그대로 지켜 주세요.

제안 은 저희 판단일 뿐입니다. 참고만 하시고 실제 설계는 담당자분이 정하시면 됩니다. 그대로 구현하지 않으셔도 괜찮습니다.

먼저 이것 하나만 기억해 주세요.

지도에서 "닮은 향수" 를 좌표 거리로 계산하면 안 됩니다. 향수마다 families 옆에 미리 계산된 목록이 붙어 있으니 그걸 쓰세요.

좌표는 향수 200개를 평면에 눌러 담은 결과입니다. 가까운 것끼리 가깝게 놓는 것은 지켜지지만 거리 값 자체가 향의 차이를 뜻하지는 않습니다. 그래서 "2배 멀다" 가 "2배 다르다" 가 아니고, 지도 반대편끼리의 거리는 대략적인 값입니다.

이 문서를 다 읽지 않아도 되는 요약

  1. 파일 2개를 받습니다 — 향수·계열 데이터 하나, 지도 배경 하나.
  2. 5단계로 그립니다 — 바다/땅 → 계열 색면 → 해안선 → 점 → 라벨.
  3. 좌표계가 두 개입니다. 향수 점과 나머지(색면·해안선·라벨)가 다릅니다. 3번에서 설명합니다.

1받는 파일 2개

scent_map.json 474 KB 향수 200개 + 향 계열 9개 bounds 좌표 범위 families[9] 계열 이름 · 영역 폴리곤 · 라벨 위치 points[200] 향수 좌표 · 소속 계열 · 닮은 향수 scent_map_terrain.json 227 KB 지도 배경 (한 번 받아 캐시) grid_width / grid_height 128 / 108 bounds 이 파일 좌표 범위 (향수 좌표보다 넓다) density.values 13,824칸 — 향수가 몰린 정도 family_grid.values 13,824칸 — 칸마다 어느 계열인지 contours 해안선

배경 파일은 지도를 다시 만들 때만 바뀌므로 한 번 받아 캐시하면 됩니다.

2이렇게 그리면 됩니다

제안 아래 5단계가 저희가 실제로 그려 본 순서입니다. 캔버스든 SVG 든 WebGL 이든 방식은 담당자분이 정하시면 됩니다.

좌표를 화면 크기에 맞추기

향수 좌표는 0~1 범위입니다. 화면 크기를 곱하면 됩니다. 다만 bounds 를 읽어서 쓰고 숫자를 코드에 적어 두지 마세요 — 지도를 다시 만들면 y 의 최대값이 바뀝니다.

// 향수 점을 화면에 놓기
const b = map.bounds;
const px = (p.x - b.x_min) / (b.x_max - b.x_min) * W;
const py = (p.y - b.y_min) / (b.y_max - b.y_min) * H;

측정 현재 y_max 는 0.83056 입니다. 이전 버전은 0.57069 였습니다.

바다와 땅 칠하기

density.values 는 칸마다 0~255 숫자가 든 배열입니다. 향수가 몰린 곳이 높습니다. sea_level(71)보다 큰 칸이 땅이고 나머지가 바다입니다.

// 칸 하나 찾기 — 배경 파일의 bounds 를 쓴다 (향수 좌표의 bounds 가 아니다)
const i = row * grid_width + col;
const isLand = density.values[i] > density.sea_level;

두 가지 함정이 있습니다.

위아래가 뒤집혀 있습니다. 측정 row 0 이 아래쪽 (y_min)입니다. 화면 좌표는 보통 위가 0 이므로, 그대로 그리면 지도가 거꾸로 나옵니다. 행을 뒤집어 주세요.

여기서 255 는 바다가 아닙니다. 이 격자에서 255 는 "가장 붐비는 칸" 이라는 정상값입니다. 뒤에 나오는 계열 격자에서만 255 가 바다를 뜻합니다.

향 계열 색면 얹기

family_grid.values 도 같은 크기의 배열입니다. 칸마다 어느 계열의 땅인지가 들어 있습니다.

const v = family_grid.values[i];
if (v === 255) { /* 바다 */ }
else {
  const key = family_grid.id_to_key[v];   // "CITRUS" 같은 문자열
  fill(COLOR[key]);
}

측정 여기서는 255 가 바다입니다. 격자값은 그냥 배열 위치라 id_to_key 를 거쳐 문자열 키로 바꿔서 쓰세요. 그러면 나중에 계열이 하나 빠져도 코드가 안 깨집니다.

색은 정해진 것이 없습니다. 아래는 저희가 검토용으로 쓴 값이니 디자인에 맞게 바꾸세요.

시트러스프루티플로럴그린·아로마틱아쿠아틱우디앰버·스파이시구르망머스크·파우더리

해안선 그리기

contours 에 해안선이 들어 있습니다. 안 그려도 되지만 있으면 지도처럼 보입니다.

고리가 닫혀 있지 않습니다. 측정 해안선 조각 4개 중 3개가 열려 있습니다 (지도 가장자리에서 잘린 것들입니다). 감기 방향이나 구멍 표시도 없습니다.

closePath() 를 직접 불러 주세요. 안 그러면 칠할 때 이상하게 나옵니다.

계열 영역의 polygon 도 같습니다 — 조각이 1~5개이고, 작은 조각(정점 5개)은 다른 계열 안에 섬처럼 박힌 영역이라 일부러 남긴 것입니다. 노이즈가 아닙니다.

점과 라벨 붙이기

향수 200개를 points 로 찍습니다. koreaRank(1~200)를 점 크기나 이름 표시 우선순위에 쓸 수 있습니다.

계열 이름은 families[].anchor 위치에 붙입니다. 측정 9개 전부 자기 계열 땅 위에 있습니다 — 별도 배치 계산이 필요 없습니다.

앵커와 폴리곤은 향수 좌표와 좌표계가 다릅니다. 배경 파일의 bounds 를 써야 하고, 측정 -0.04565 같은 음수가 나옵니다. 향수 점의 bounds 로 변환하면 위치가 어긋납니다.

3좌표계가 두 개인 이유

헷갈리기 쉬운 부분이라 따로 적습니다.

향수 점은 딱 0~1 에 맞춰 정규화되어 있습니다. 화면에 곱해서 쓰기 좋게 만든 값입니다.

지도 배경은 그보다 조금 넓습니다. 땅의 밀도를 계산할 때 가장자리 향수도 주변에 여유가 있어야 자연스러운 해안선이 나오기 때문에, 사방으로 0.05 만큼 여백을 두고 격자를 만들었습니다. 그래서 색면·해안선·라벨 위치는 이 넓은 좌표계에 있고 음수가 나옵니다.

// 향수 점        map.bounds          x 0 ~ 1        y 0 ~ 0.83056
// 배경 · 색면 · 해안선 · 라벨
                    terrain.bounds      x -0.05 ~ 1.05   y -0.05 ~ 0.88056

둘 중 하나로 통일해 쓰고 싶으면, 배경 쪽 좌표계로 향수 점을 옮기는 편이 쉽습니다 (같은 변환식에 terrain.bounds 를 넣으면 됩니다).

4실제로 그려 본 것

아래 지도는 드리는 파일 2개만으로 이 문서 안에서 직접 그린 것입니다. 위의 5단계를 그대로 따랐습니다.

시트러스프루티플로럴그린·아로마틱아쿠아틱우디앰버·스파이시구르망머스크·파우더리바다

칠한 땅 칸 · 향수 개 · 계열 라벨 개. 격자 128×108.

5좁은 화면에서 라벨이 걸립니다

측정 저희가 뷰포트 3개(375 · 768 · 1280)에서 라벨 배치를 돌려 봤습니다. 768px 이상에서는 계열 이름 9개가 전부 겹치지도 잘리지도 않습니다.

모바일(375px)에서만 3개가 화면 밖으로 나가 안으로 당겨집니다 — 플로럴 · 앰버·스파이시 · 아쿠아틱입니다. 영역이 작아서가 아니고 그 계열의 라벨 위치가 지도 가장자리에 붙어 있어서입니다 (아쿠아틱은 왼쪽 끝 x = 0.011, 플로럴은 오른쪽 끝 x = 0.972). 걱정했던 작은 계열은 375px 에서도 전부 라벨이 들어갈 만큼 넓었습니다.

또 우디와 앰버·스파이시의 라벨이 가장 가깝습니다 — 간격이 375px 지도에서 46px 인데 "앰버·스파이시" 7자가 약 70px 이라 겹칩니다.

확인이 필요한 것 — 모바일 라벨

아직 정하지 않았습니다. 세 가지 중에 어느 쪽이 나을지 의견 주세요.

  • 범례로 빼기 — 지도 밖에 계열 목록을 두고 지도에는 색면만
  • 줌 인했을 때만 표시 — 멀리서는 색면, 가까이 가면 이름
  • 짧은 이름 쓰기 — "앰버·스파이시" 대신 "앰버"

저희 생각은 두 번째와 세 번째를 같이 쓰는 쪽이지만, 화면을 만져 보시는 분 판단이 맞다고 봅니다.

그 밖에 확인이 필요한 것

  • 지도 배경을 정적 파일로 받을 수 있나요. API 응답에 섞는 것보다 캐시가 잘 되어 그렇게 제안했습니다.
  • 줌 단계를 몇 개로 할까요. 저희 프로토타입은 3단계였습니다 — 멀리(색면+라벨) · 중간(+점) · 가까이(+향수 이름).
  • 격자를 그대로 쓸지, 이미지로 미리 구워 둘지. 칸이 13,824개 × 2장이라 매 프레임 다시 칠하면 느릴 수 있습니다. 저희는 한 번 칠해 두고 재사용했습니다.
