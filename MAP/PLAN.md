> 표기 규칙
> - **[확정]** — 데이터/노트북 실행 출력에서 직접 확인한 사실

## Context

향해의 핵심 탐색 기능인 향 지도를 구현한다. 사용자가 아는 향수에서 출발해 주변의 비슷한 향수를 발견하는 경험이 목표다.

`MAP/`에서는 **좌표·유사도 등 데이터 산출 로직만** 담당한다. **제품 UI는 만들지 않는다** — 화면 렌더링은 다른 팀원이 별도로 구현 중이다. 단, 우리가 만든 좌표가 실제로 말이 되는지 확인할 **검증용 뷰어는 만든다**(Step 4.5). 수치 지표만으로는 "이 향수 주변 배치가 납득되는가"를 잡아낼 수 없기 때문이며, 이 뷰어는 산출물이 아니라 진단 도구다.

조사 결과 이 작업의 성격이 처음 가정과 다르다는 점이 확인됐다.

**향 지도는 새 유사도 정의가 필요한 작업이 아니다.** 팀은 이미 `reminds_me_of`(사용자가 "이 향수가 저 향수랑 비슷하다"고 투표한 데이터)를 정답으로 삼아 향수-향수 유사도 함수를 만들고 측정까지 끝냈다(EDA 04~06). 향 지도가 새로 푸는 문제는 **"검증된 고차원 유사도를 2D로 떨어뜨렸을 때 그 구조가 얼마나 보존되는가"** 하나다.

따라서 이 플랜의 핵심은 유사도 설계가 아니라 **기존 유사도 재사용 + 2D 투영의 왜곡 측정**이다.

### 1.3 Accord

**[확정]**

- 고유 accord **92종**.

**[확정] 중요한 한계** — accord 목록에 없다는 것은 "그 향이 없다"가 아니라 "주요 8개 안에 기록되지 않았다"이다(EDA 03에 명시). 8개 상한 때문에 accord 벡터의 표현력에는 천장이 있다.

### 1.5 평가 정답 라벨 — `reminds_me_of`

**[확정]** (JSONL 전체 스트리밍으로 직접 측정)

- 보유 향수 91,603개(69.4%), directed relation 692,729건.
- `people >= 500`인 7,823개 중 **7,420개(94.8%)**가 최소 1개 보유, 평균 18개.
- **EDA가 이미 확정한 "정답 pair" 기준: `total_votes >= 20 AND agree_ratio >= 0.8`** → undirected 10,770 pair.

**[확정] 결정적 제약 — Negative label이 존재하지 않는다.**
`agree_ratio <= 0.2` & `total_votes >= 20`인 pair가 **0건**이다(0.1/0.2/0.3 모두 0건). 즉 "안 닮았다"는 근거로는 쓸 수 없고 **positive-only relevance label**로만 써야 한다. EDA 03에서 ROC-AUC가 NaN으로 계산 불가였던 이유다.

**[확정] 지도 규모별 정답 간선 밀도 (직접 측정)** — 이번 플랜의 규모 결정 근거:

| 대상 집합 | 집합 내부 간선 | 신뢰 간선(up≥3, up>down) | 간선 보유 노드 | 신뢰 간선 보유 노드 |
|---|---|---|---|---|
| 인기 top 200 | 203 | 94 | 111 / 200 | **70 / 200** |
| 인기 top 500 | 830 | 344 | 351 / 500 | 211 / 500 |
| **인기 top 1000** | **2,425** | **943** | **819 / 1000** | **483 / 1000** |
| 인기 top 2000 | 7,393 | 2,611 | 1,802 / 2000 | 1,145 / 2000 |

→ **200개만으로는 지도 배치 품질을 데이터로 검증할 근거가 얇다.** 1000개면 검증이 가능해진다.

### 1.6 알려진 데이터 함정

**[확정]**

1. **`people = null` 10,405건(7.89%)이 CSV에서 0으로 저장돼 있다.** 해당 ID의 longevity/sillage/price_value/seasons/daypart가 전부 0이지만 이는 "0표"가 아니라 "데이터 없음"이다. **CSV만으로는 구분 불가** — JSONL의 null을 봐야 한다.
2. 별도로 "people 존재 & season_total = 0"인 진짜 0표가 10,174건 있다.
3. 저투표 향수가 대다수다. `people` 중앙값 15, `people >= 20`이 41.6%뿐. 커뮤니티 필드는 저투표 구간에서 신뢰 불가.
4. `reminds_me_of`의 1000 이상 투표수는 페이지가 축약 표기해 **근사값**이다(SCHEMA 명시).
5. **인기 top-N은 편향돼 있다** (직접 측정): top200은 85개 dominant accord 중 **28개만** 커버, 브랜드 76개 중 상위 10개가 44.5% 차지(Chanel 14, Dior 13, Armani 10). 전체 코퍼스 대비 vanilla/sweet가 과대표집.

## 2. 이미 검증된 자산 — 재구현하지 말 것

**[확정]** EDA 04~09는 **향수-향수 유사도**를 `reminds_me_of` 정답으로 평가한 실험이다. 향 지도가 필요로 하는 바로 그 함수다.

### 2.1 확정된 Base Similarity

```
sim(a, b) = 0.5 · cosine(accord_strength_L2정규화)
          + 0.5 · idf_weighted_jaccard(note union)
```

- accord: 92차원, **raw strength**(0~100), 행 L2 정규화
- note: 2,523차원 binary, top/middle/base/flat의 **합집합**, IDF 가중 Jaccard
- IDF: `log((N+1)/(df+1)) + 1`, N = 131,930

### 2.2 측정된 실험 결과 (Development 700 queries)

| 모델 | Recall@10 | HitRate@10 | NDCG@10 |
|---|---|---|---|
| Popularity | 0.0167 | 0.0443 | **0.0113** |
| Accord Cosine | 0.1868 | 0.4071 | 0.1688 |
| Note Jaccard | 0.2545 | 0.5029 | 0.2345 |
| **Accord + Note (0.5/0.5)** | **0.2900** | **0.5500** | **0.2668** |

Internal Validation 200에서 Raw Accord + IDF Note 채택 시 Recall@10 **0.3270** / NDCG@10 **0.2760** (paired bootstrap CI가 0을 포함하지 않음).

### 2.3 이미 기각된 선택지 — 다시 시도할 이유 없음

| 시도 | 결과 | 출처 |
|---|---|---|
| Popularity를 유사도로 사용 | NDCG@10 0.0113 — **사실상 무의미** | 04 |
| Note tier(top/middle/base) 가중 | β 스윕이 **단조 감소**(0.2709 → 0.2561), 5/5 fold 개선 없음. 정답 pair 공통 note의 88.14%가 이미 같은 tier | 06 |
| Accord에 IDF 적용 | 0.2688 → 0.2603 하락 | 05 |
| Score calibration (minmax/zscore/percentile) | RAW 대비 −0.0254, CI [−0.0325, −0.0186] | 09 |

### 3.2 벡터화 — **결정됨**

**[제안]** accord는 raw strength L2 정규화, note는 IDF 가중 binary 합집합. **tier 가중과 accord IDF는 이미 측정으로 기각됐으므로 재시도하지 않는다**(§2.3).

**[제안]** note canonical map 적용 여부는 **측정 후 결정**한다. `fragrantica_note_canonical_map_v1.csv`의 SAME_CONCEPT 48건만 병합(REVIEW/NOT_SAME는 병합 금지)하고, 적용 전후로 §4 Step 1의 재현 지표를 비교한다. 개선이 측정되지 않으면 적용하지 않는다.

### 3.3 2D 배치 방식

**[제안] UMAP을 주 방법으로 채택한다.**

> 초안에서는 MDS를 추천했으나 **실제 거리 행렬을 측정한 뒤 뒤집었다.** 근거는 아래와 같다.

#### 측정: 우리 거리 행렬의 모양

**[확정]** 인기 top1000으로 Base Similarity 거리행렬(499,500 pair)을 직접 계산한 결과:

| 항목 | 값 |
|---|---|
| 거리 평균 / 표준편차 | **0.824 / 0.107** (변동계수 0.13) |
| 백분위 25 / 50 / 75 / 95 | 0.752 / 0.837 / 0.908 / 0.975 |
| 1번째 최근접 이웃 평균 거리 | **0.466** |
| 20번째 최근접 이웃 평균 거리 | **0.596** |
| 중앙값 파트너 거리 | **0.837** |

→ **의미 있는 국소 신호는 0.47~0.60 구간에만 있고, 나머지 전체가 0.84 근처에 뭉쳐 있다.**

결정적인 수치:

- 국소 신호 구간(1~20번째 이웃) 안에 드는 pair는 전체의 **2.77%**
- 그런데 이들이 차지하는 **제곱거리 합(= MDS의 stress 목적함수 질량)은 단 1.24%**

**즉 MDS는 최적화 노력의 약 98.8%를 "서로 멀고 다 비슷하게 먼", 정보가 없는 pair에 쓴다.** 제품이 실제로 신경 쓰는 최근접 10~20개 이웃 구조는 목적함수의 1% 정도밖에 안 된다. 고차원 희소 데이터의 전형적인 거리 집중(distance concentration) 현상이고, 전역 stress 기반 방법이 잘못된 도구가 되는 조건이다.

**더 구체적인 실패 예측 [확정]** — 두 성분을 분리해 재보면:

| 성분 | 거리 평균 | 표준편차 | d < 0.8 비율 |
|---|---|---|---|
| accord cosine | 0.694 | 0.195 | **65.6%** |
| **IDF note Jaccard** | **0.954** | **0.048** | **1.1%** |

note 성분은 거의 전부 "멀다"에 포화돼 있고 정보가 얇은 꼬리에만 있다. 그런데 **EDA 측정에서 더 강한 신호였던 쪽이 note다**(NDCG@10 0.2345 vs accord 0.1688, §2.2). MDS로 배치하면 퍼짐이 큰 accord 구조가 지도를 지배하고 **더 중요한 note 구조가 사실상 버려진다.**

#### 방법 비교

| 방법 | 장점 | 단점 | 난이도 |
|---|---|---|---|
| **UMAP** (`metric='precomputed'`) | **kNN 그래프를 먼저 만들고 국소 관계만 모델링** — 위의 정보 없는 bulk를 아예 보지 않는다. 제품 목표("아는 향수 주변 탐색")와 목적함수가 일치. 클러스터 간 상대 배치도 t-SNE보다 잘 유지돼 "향 계열 영역"을 그리기에 적합 | 새 의존성. 파라미터 2개(`n_neighbors`, `min_dist`) 스윕 필요. 소규모 N에서 가짜 클러스터가 생길 수 있음 | 중간 |
| t-SNE (`sklearn`, 기설치) | 국소 보존 강함. 의존성 없음 | **클러스터 간 거리에 의미가 전혀 없음** — 계열 영역 배치가 무의미해짐 | 중간 |
| Metric MDS (`sklearn`, 기설치) | stress가 해석 가능. 파라미터 없음 | **위 측정으로 부적합 확인** — 목적함수 질량의 1.2%만 국소 구조. note 신호 소실 예상 | 낮음 |
| PCA | 가장 단순, 결정적 | 우리 거리(cosine+Jaccard 혼합)가 유클리드가 아니라 부적합 | 최저 |

#### CLAUDE.md와의 정합성

이 판단을 굳히는 건 기획 문서다.

> "현재 단계에서는 주요 향 계열 **내부에서** 향수 사이의 관계를 표현하는 것을 우선한다. 서로 다른 모든 향 계열을 하나의 완벽한 좌표 체계로 연결하는 것은 현재 **필수 요구사항이 아니다**."

전역 좌표 일관성이 요구사항이 아니라고 명시돼 있다. 그게 MDS의 유일한 강점이었고, 우선 요구사항인 "계열 내부 관계"는 정확히 UMAP이 최적화하는 대상이다. **초안에서 제가 이 문장의 무게를 잘못 쟀다.**

#### UMAP 채택으로 포기하는 것 [제안]

솔직히 정리하면, "지도상 거리 = 유사도"라고 **말할 수 없게 된다.** UMAP 좌표는 거리 척도가 아니다. 다만 이건 이미 §3.6·Step 4에서 대비하고 있다 — 정확한 "비슷한 향수" 답은 2D 거리가 아니라 고차원 기준 `neighbors` 배열이 담당한다. 그리고 애초에 MDS로도 이 데이터에선 낮은 stress를 얻을 수 없다는 게 위 측정 결과다. **실질적으로 잃는 건 없다.**

#### 파라미터와 환경 [제안]

- `metric='precomputed'`, `random_state` 고정(재현성 확보, N=1000이라 병렬성 손실은 무시 가능).
- `n_neighbors`: **10 / 15 / 30** 스윕. 작을수록 국소 파편화, 클수록 전역 구조. §3.6 지표로 고른다.
- `min_dist`: **0.1 / 0.3**. 점 겹침에 영향을 주므로 지도 가독성 기준으로 병행 확인.
- **소규모 N에서 UMAP이 가짜 클러스터/찢김을 만들 수 있다**는 알려진 위험이 있다. 단일 실행을 믿지 말고 여러 `n_neighbors`에서 지표가 일관되는지 본다.

**[제안] `umap-learn`을 EDA/venv에 설치하지 않는다. `MAP/` 전용 venv를 새로 만든다.**
`umap-learn`은 `numba`/`llvmlite`를 끌어오는데, 현재 EDA venv는 **numpy 2.4.6**이고 numba는 보통 numpy 상한을 건다. 팀 공용 venv에서 numpy가 다운그레이드되면 **기존 노트북 23개가 모두 영향을 받는다**. `MAP/venv`를 따로 두면 이 위험이 사라진다. 설치가 실패하면 t-SNE가 대체재다(sklearn 기설치, 국소 보존은 확보되고 계열 간 배치만 포기).

**[제안] PCA와 random layout은 비교 하한으로 계속 계산한다.** 절대 수치만으로는 "좋다"를 말할 수 없다. MDS도 **비교군으로만** 한 번 돌려 위 예측(note 구조 소실)이 실제로 나타나는지 확인한다 — sklearn에 이미 있어 비용이 거의 없고, 이렇게 해야 "UMAP이 낫다"가 주장이 아니라 측정이 된다. 일정이 밀리면 MDS 비교는 버려도 된다.

### 3.4 season/daypart 사용 여부

**[확정]** EDA 07/09에서 season+daypart는 **reranking 신호로는 유효**했다(reliable ≥20표, gamma 0.5에서 NDCG@10 0.2709 → 0.3164, 5/5 fold 개선). 그러나 base 점수와 상관이 **0.094**로 거의 독립이며, **후보 검색이 아니라 TOP 200 재정렬에만** 쓰였다. 07 cell 18에 그 이유가 명시돼 있다 — 사용 상황이 비슷한 향수가 냄새까지 비슷하진 않다.

**[제안] 1차 지도에는 넣지 않는다.** 두 개의 거의 독립인 신호를 하나의 2D 좌표에 섞는 것은 검증된 적 없는 영역이고, 실패 시 원인 분리가 불가능해진다. 좌표는 냄새 유사도만으로 만들고, season/daypart는 **필터/표시 속성**으로 JSON에 실어 프론트가 쓰게 한다.

### 3.5 대상 향수 선정

**[확정]** 화면 200개 + 좌표 1000개 계산 (사용자 결정).

**[확정] 선정 방식: accord 계열별 할당 후 계열 내 인기순** (사용자 결정).

**[제안] 화면 200개도 같은 규칙을 적용한다** — 각 계열에서 인기 상위를 뽑아 200개를 구성한다. 1000개는 계열 균형을 맞춰놓고 화면 200개만 인기순으로 뽑으면 사용자가 처음 보는 지도에 다시 빈 구역이 생겨 결정 취지가 사라진다. 계열 수(58종)를 감안하면 계열당 3~4개 수준이다.

### 3.6 평가 방법 — 가장 중요한 결정

**[제안]** 서로 다른 두 질문을 분리한다. 섞으면 실패 원인을 못 찾는다.

**E1. 유사도 함수가 맞는가?** → **이미 답이 나와 있다**(§2.2). 다시 측정하지 않는다. Step 1에서 *재현*만 확인한다.

**E2. 2D 투영이 그 구조를 보존하는가?** → 향 지도가 새로 만드는 유일한 질문. 세 지표로 측정한다.

1. **Trustworthiness@k** (`sklearn.manifold.trustworthiness`, k=10/20)
   — "2D에서 가까운 점이 실제로도 가까운가". 제품 주장과 1:1 대응한다.
2. **kNN overlap@k** = `|kNN_2D ∩ kNN_고차원| / k`의 평균
   — 해석이 가장 직관적. 프론트가 지도 이웃을 그대로 보여줘도 되는지 판단 근거.
3. **`reminds_me_of` 신뢰 pair의 2D 거리 백분위**
   — top1000 내부 신뢰 간선 943개에 대해, 파트너의 2D 거리 순위를 무작위 pair 분포와 비교. **사람이 투표한 정답이 지도에서도 가까운가**를 직접 본다.

**[제안] 비교 하한을 반드시 같이 계산한다** — random layout과 PCA layout. 절대 수치만으로는 "좋다"를 말할 수 없다. `random < PCA < UMAP`이 세 지표 모두에서 나와야 배치가 의미 있다고 말할 수 있다.

**[확정] `also_liked`는 진단 지표로만 측정한다** (사용자 결정). top1000 내부 간선이 19,827개로 `reminds_me_of`(2,367)보다 8배 조밀해 정답이 없는 향수까지 덮지만, **투표가 없는 알고리즘 출력이라 "냄새가 닮았다"의 근거가 아니다**(인기·취향이 섞여 있음). 합격 판정에는 쓰지 않고, `reminds_me_of` 지표와 **같은 방향으로 움직이는지**만 본다. 두 지표가 일치하면 결과 신뢰도가 올라가고, 어긋나면 그 사실 자체가 분석 대상이다.

**[제안] 목표 수치를 미리 만들지 않는다.** 측정 전에 "trustworthiness 0.9 달성" 같은 숫자를 정하면 근거 없는 기준이 된다. random/PCA 대비 우위와 실제 측정값을 그대로 기록한다.

**완료 확인**: `import umap` 성공 및 EDA/venv 미변경 확인. 대상 1000행, id 중복 0, accord·note 보유 1000/1000, `display` 200개. **§3.5 측정치 재현** — 계열 58종, 브랜드 219, 집합내 간선 2,367 / 신뢰 896. 어긋나면 선정 로직이 다른 것이다.

### Step 1 — Base Similarity 재현 (1일)

- `X_accord` (1000×92, raw strength L2 정규화), `X_note` (1000×2523 binary, IDF는 `10_note_dictionary.csv` 재사용).
- `sim = 0.5·cos + 0.5·idf_weighted_jaccard`, 거리 `d = 1 − sim`.

**완료 확인 (known-answer test)**: 전체 코퍼스로 한 번 확장해 EDA 04/05의 Development 700 query 평가를 재실행하고 **NDCG@10 ≈ 0.2688, Recall@10 ≈ 0.29**가 재현되는지 본다. 크게 어긋나면 재구현이 틀린 것이다. 이 단계를 건너뛰면 이후 모든 측정이 무의미하다.

> §3.2의 canonical map 적용 여부도 이 지표로 A/B 판단한다.

### Step 2 — 2D 배치 (1.5일)

- 1000×1000 거리행렬 → **UMAP** (`metric='precomputed'`, `random_state` 고정).
- `n_neighbors` ∈ {10, 15, 30} × `min_dist` ∈ {0.1, 0.3} = 6개 조합.
- **비교군으로 random layout, PCA layout, MDS도 생성**한다.

**완료 확인**: 모든 레이아웃에 대해 trustworthiness@10/@20, kNN overlap@10, `reminds_me_of` 신뢰 pair 거리 백분위를 계산해 한 표로 남긴다.
- 합격 조건: **채택 UMAP 설정이 세 지표 모두에서 random과 PCA를 명확히 상회**.
- `n_neighbors` 3개 값에서 **지표가 일관되게 나오는지** 확인한다(§3.3의 가짜 클러스터 위험 대응). 한 설정에서만 잘 나오면 그 결과를 믿지 않는다.
- MDS 결과에서 §3.3의 예측(accord 구조 지배, note 구조 소실)이 실제로 나타나는지 기록한다. 예측이 빗나가면 그것도 그대로 남긴다.
- UMAP이 PCA를 못 이기면 개선을 주장하지 않고 그 사실을 기록한 뒤 원인을 본다.

### Step 3 — 클러스터 라벨 (0.5일)

- Agglomerative clustering (`metric='precomputed'`, `linkage='average'`) — 배치에 쓴 것과 **같은 거리**를 쓴다. 좌표가 아니라 고차원 거리에 적용한다.
- **[확정]** k 후보 **8 / 12 / 16을 모두 돌린 뒤 accord 구성표를 보고 선택**한다(사용자 결정). 선택 근거를 `DECISIONS.md`에 남긴다.
- **[확정] 클러스터 라벨은 상위 accord 3개만 내보낸다**(사용자 결정). 예: `["woody", "warm spicy", "amber"]`. 데이터에서 직접 나온 사실만 담아 검증 가능하고, 한국어 이름은 기획이 나중에 붙일 수 있다.

**완료 확인**: 클러스터별 상위 accord 표를 출력해 (a) 서로 구분되는지, (b) 2D 상에서 심하게 뒤섞이지 않는지 확인. 클러스터와 dominant accord(58종)의 교차표를 만들어 **계열 할당이 실제로 지도상 영역 분산으로 이어졌는지** 확인한다 — 이어지지 않았다면 계열 정의(dominant accord)가 냄새 구조와 안 맞는다는 뜻이므로 기록한다.

> **클러스터에 "깊은 숲" 같은 한국어 이름을 임의로 붙이지 않는다.** CLAUDE.md의 "근거 없는 scent inference 금지"에 해당한다. accord 구성만 산출하고 네이밍은 기획 결정으로 넘긴다.

### Step 4 — 이웃 목록 및 JSON 산출 (0.5일)

**[제안] `neighbors`는 2D 거리가 아니라 고차원 유사도 상위 K로 만든다.** 2D 왜곡은 불가피하므로, 지도는 탐색용이고 "비슷한 향수" 정답은 이 배열이다. 이 구분이 UX 정확도를 지킨다.

**[확정] 좌표는 [0,1]로 정규화하되 x·y에 같은 배율을 적용한다**(사용자 결정). 축별로 따로 정규화하면 종횡비가 깨져 **UMAP이 만든 거리 구조가 그대로 왜곡된다.** 두 축의 범위 중 넓은 쪽을 기준으로 같은 배율로 축소하고 좁은 축에는 여백을 둔다. 즉 결과의 x 또는 y 중 한쪽만 [0,1]을 꽉 채운다.

### Step 5 — (조건부) 배치 품질 부족 시 대응 (1일)

Step 2에서 UMAP이 PCA를 확실히 이기지 못하거나 `n_neighbors` 간 지표가 흔들릴 때만 수행한다. 순서대로 본다.

1. **t-SNE 비교** (`sklearn`, `metric='precomputed'`) — 같은 지표·같은 프로토콜. 국소 지표에서 **측정으로 이겼을 때만** 교체하고, 교체 시 "클러스터 간 거리는 의미 없음"을 프론트 전달 문서에 명시한다.
2. **원인이 배치가 아니라 거리행렬인지 확인** — §3.3 측정대로 note 성분은 pair의 1.1%만 d<0.8이다. 2D 이전에 이미 신호가 얇을 가능성이 있으므로, accord-only / note-only 거리로 각각 배치해 어느 쪽이 구조를 만드는지 분리한다.
3. 그래도 부족하면 대상 1000개 선정 기준(§3.5)을 의심한다. 인기 편향으로 계열이 뭉쳐 있으면 어떤 배치 방법도 구조를 못 만든다.

**측정 없이 방법을 계속 바꾸지 않는다.** 세 가지를 다 해도 지표가 낮으면 그 사실을 그대로 보고한다.

### Step 6 — (최종 1회) Holdout 확인
